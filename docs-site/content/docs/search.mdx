## 快速搜索

输入文档中的词语即可开始本地搜索。快速搜索无需配置模型密钥，适合查找名称、术语和已知内容。

![搜索结果与原文高亮](/images/product-search-cn.png)

搜索结果按文件归组，点击结果在右侧阅读原文。点击“相关片段”可选择同一文件的命中片段；原文顶部的匹配导航可继续切换位置。文档操作菜单提供“打开文档”和在文件夹中显示的入口。

## 阅读搜索结果

- 拖动结果列表与原文之间的分隔线调整宽度；切换文件后会恢复本次搜索中的阅读位置。
- 使用原文顶部的文内查找、相关片段和专注阅读按钮，集中查看命中内容。
- 大文档优先显示目标段落，其余内容逐步加载；窄窗口可通过返回按钮回到结果列表。

## 深入检索

先在模型设置中配置 Jev 服务、模型和 API Key，再选择深入搜索。使用完整问题描述需要查找的内容，例如：

```text
这个项目如何处理登录与权限？
```

SAG2 检索会召回候选原文，通过 Jev 判断证据相关性，按需扩展查找范围，再返回相关来源。它适合需要跨文件查找的问题。

## 两种搜索的区别

| 项目 | 快速搜索 | 深入检索 |
| --- | --- | --- |
| 输入 | 词语、名称、明确内容 | 完整问题或语义描述 |
| 执行 | 本地全文检索 | 本地索引与 Jev 服务 |
| 服务配置 | 无需模型密钥 | 需要 Jev 配置 |
| 输出 | 匹配文件与原文 | 与问题相关的证据来源 |

## 查看耗时

界面显示搜索用时和处理状态。问答中的工具耗时还包含工具请求本身的处理过程，比较不同入口时应同时核对问题、范围和检索配置。

## 搜索设置详解

入口：**设置 → 搜索设置**。先阅读 [技术科普](/zh/docs/sag2)，理解候选、扩展和最终结果的区别。

![自动总结和 SAG2 检索参数](/images/product-search-settings-cn.png)

### 搜索结果自动总结

默认开启。搜索后调用问答模型，根据问题和参考结果生成简短总结。它是检索结束后的独立步骤：关闭后仍可以搜索、查看原文，且不会为搜索总结调用回答模型。

使用自动总结需要先配置[回答模型](/zh/docs/models)，可能产生对应服务费用。不要把总结用时与纯检索用时混为一项。

### 自动总结参考数量

默认 10 条，最小 1，没有固定最大值。决定最多取多少条搜索结果作为总结参考；当超过回答上下文预算时，应用会裁剪输入。增大数量不保证总结更好，也会增加输入量。

### SAG2 参数

| 设置 | 默认值 / 范围 | 作用与调整影响 |
| --- | --- | --- |
| 每轮候选数量 | 50 / 10–100 | 问答检索每轮的新候选上限。增大可扩大评分范围，也增加 Jev 处理量。桌面深入搜索固定为 100，不受此项改变。 |
| 扩展起点数量 | 10 / 1–20 | 每轮从评分结果中选择多少个尚未扩展的片段，作为继续检索的起点。更多起点会带来更多上下文与词项。 |
| 扩展词上限 | 20 / 1–500 | 控制从起点提取的词项和完整名称短语数量。增大可扩展查询，也可能引入更多无关候选。 |
| 扩展轮数 | 1 / 0–2 | 初次召回之后再扩展多少轮。0 为仅首次检索；1 为最多 2 轮；2 为最多 3 轮。没有新候选时提前结束。 |
| 返回片段数量 | 10 / 1–100 | 问答检索工具最终返回多少个片段。它不决定每轮召回数量。桌面深入搜索最多展示 100 个文件；CLI 可用 `-m` 指定输出上限。 |
| 片段目标字符数 | 512 / 400–12000 | 建库切分时的目标长度。保留完整句子与相邻上下文，长句可超过目标。修改后自动重建索引。 |

### 如何调整

先使用默认参数。在固定问题与文件范围下，一次只改一项，并对比原文是否覆盖问题所需事实及总耗时。

- 返回内容太多：先降低返回片段数量，不必同时减少候选范围。
- 需要跨文件补充事实：可以检查扩展轮数和起点数量。
- 单个片段缺少上下文：可以调整片段目标字符数，但需等待重新索引。
- 检索太慢：检查候选数量、扩展轮数和 Jev 服务耗时。

### 恢复默认参数

把六项 SAG2 参数恢复为 `50 / 10 / 20 / 1 / 10 / 512`。随后点击保存设置。此按钮不重置自动总结开关和总结参考数量；若片段长度发生变化，会触发索引更新。

### 轮数与请求数量

当前实现最多进行 3 轮 Jev 评分，本地最终排序不额外调用模型。同一轮候选过多时会按请求预算分批，保留完整候选；一个候选连同共享证据仍超出预算时，会明确报错而不截断原文。

因此，界面上的检索轮数不等于实际 Jev HTTP 请求数量。更大的候选、起点或片段可能增加批次与耗时。
