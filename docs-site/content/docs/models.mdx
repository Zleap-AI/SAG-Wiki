## 两类模型的分工

入口：**设置 → 模型设置**。

| 配置 | 用途 | 什么时候需要 |
| --- | --- | --- |
| 问答模型（LLM） | 组织回答、调用工具、生成搜索总结 | 问答、启用自动总结的搜索 |
| 决策模型 | 判断候选原文是否提供问题所需的证据 | SAG2 深入检索、CLI 语义搜索 |

本地索引与快速搜索不需要这两类模型。只有决策模型配置也可以进行语义检索；只有问答模型无法完成依赖决策模型的 SAG2 检索。

![回答模型的供应商、地址和模型名称设置](/images/product-models-cn.png)

## 逐项填写

### 供应商

选择供应商后会填入对应接口地址。问答模型提供 OpenAI、DeepSeek、GLM、OpenRouter、302.AI 和自定义；决策模型提供 Zleap、OpenAI、302.AI、OpenRouter、Typesafe 和自定义。首次启动默认选择 Zleap；已有用户的服务地址和模型配置保持不变。

问答接口和决策模型判断接口是两类接口，不能只因供应商相同就互换地址。自定义服务必须兼容对应接口。

### 接口地址

填写供应商提供的 API 基础地址，而非网页聊天地址。预设地址会随供应商选项填写；使用代理或自建服务时，确认路径与服务协议一致。

问答模型默认使用 Chat Completions。需要 Responses 时，填写完整接口地址（如 `https://api.openai.com/v1/responses`，代理服务则使用其对应地址）。该地址启用 Responses 流式回答、工具调用与推理状态回传；思考强度使用 `reasoning.effort`，界面的“极高”对应 `max`。GPT-6 Astra 与 GPT-6.1 Sol 不提供关闭推理档位。支持的档位由实际模型与服务决定，不支持时请恢复默认或选择服务支持的档位。仅填写 `/v1` 仍使用原来的 Chat Completions 接口。

切换到不同服务来源后，需要填写新供应商的 API Key。应用不会把原供应商密钥直接用于新的来源。

决策模型可填写基础地址（如 `http://127.0.0.1:8000/v1`），也可填写完整的 `/systemone` 或 `/decisions` 接口地址，程序不会重复追加接口路径。

### 决策模型鉴权方式

- **API Key**：用于需要密钥的服务，保留已有配置的默认方式。
- **无需鉴权**：用于不要求密钥的本地决策模型服务。此模式不发送鉴权头，保存后移除已存储的决策模型密钥。

服务需兼容决策模型判断接口。CLI 对应命令为 `sag config --url http://127.0.0.1:8000/v1 --model YOUR_MODEL --auth none`；切回密钥服务使用 `--auth bearer --key-stdin`。

### 可选模型与模型名称

问答模型的 **可选模型 · 每行一个** 决定界面里可以切换哪些模型。每行填写一个服务支持的准确模型 ID，不加逗号；去重后保存。连接测试使用列表第一项。

点击 **获取模型列表**，可用当前接口地址和 API Key 从供应商获取模型。弹窗支持搜索和多选，勾选后直接追加到可选模型，保留已有条目。点击 **完成** 关闭弹窗，再点击 **保存设置** 生效。如果供应商不提供模型列表，仍可手动填写。

决策模型的 **模型名称** 填写一个决策模型 ID。首次默认使用 Zleap 开放平台的 `Zev-1`，地址为 `https://api.zleap.com/v1`，实际请求 `/v1/systemone`。参见[决策模型文档](https://platform.zleap.com/docs/decision)。切换供应商时，Zleap 填入 `Zev-1`，OpenAI 填入 `gpt-6-luna`，302.AI 和 Typesafe 填入 `jev-latest`，其余由用户填写。仅打开设置不会覆盖已保存的模型名称。

要使用 [OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions)，在决策模型中选择 **OpenAI**，确认地址是 `https://api.openai.com/v1/decisions`，填写 OpenAI API Key，测试连接后保存。启用后，使用决策模型的检索会将问题和相关原文片段发送给 OpenAI。

<Callout title="推广">
[Zleap 开放平台](https://platform.zleap.com)现已提供自研和自部署的决策模型 **Zev-1**，全方位优于 Jev 模型，欢迎大家试用。
</Callout>

### API 密钥

选择 Zleap 时，点击 **获取 API Key** 打开[开放平台控制台](https://platform.zleap.com/console)，创建并填写该平台的密钥。Zleap 决策模型与 302.AI 问答模型的密钥分别配置。

粘贴对应服务的密钥。输入框默认隐藏，可点击显示或隐藏；已保存时留空会保留原密钥。“移除保存的密钥”会立即删除对应密钥。

两类服务都选择 302.AI 时，填写一个密钥可以自动填入尚未配置的另一项。保存前仍需确认两项服务与密钥都正确。

### 测试连接

分别点击两张配置卡片里的 **测试连接**，检查接口、模型和密钥是否可用。测试成功后点击底部 **保存设置**。测试可能发送验证请求，按供应商规则计费。
问答模型测试会请求一条简短回复；输出长度由模型服务的默认设置控制。

## 快速配置

未配置回答模型时，问答输入框右下角的模型位置显示 **快速配置**。快速入门最后一页也有同名入口。点击后可用一个 302.AI API Key 完成配置。

1. 点击输入框右上角的 **获取 API Key** 打开 302.AI 控制台创建密钥，填入输入框；眼睛图标可切换显示或隐藏。
2. 弹窗下方的“将自动写入”列出本次会配置的三项：问答模型、决策模型和文档解析。
3. 点击 **测试并保存**。客户端依次测试问答模型、Jev 决策模型和 MinerU，全部通过后才写入设置；任一项失败会在输入框下方显示原因，输入的密钥保留，不保存任何内容。

保存后问答模型使用 302.AI 的 `qwen3.8-flash`，决策模型使用 `jev-latest`，PDF 交给 302.AI MinerU 解析，三项服务共用这个密钥。已配置的 Jev 或 MinerU 保持不变，列表中显示“已配置，保持不变”。之后仍可在模型设置和文件设置中调整服务、模型和密钥。弹窗里的 **手动配置** 会直接进入模型设置。配置好回答模型后，输入框右下角会显示模型选择器。

![快速配置回答服务弹窗](/images/product-quick-setup-cn.png)

## 推荐配置顺序

1. 先配置决策模型并测试，保存后运行一次深入搜索。
2. 再配置支持工具调用的问答模型并测试。
3. 保存后在问答页选择模型，提问并检查引用来源。
4. 需要调整提示词、思考强度或工具权限时，进入[问答设置](/zh/docs/chat#问答设置详解)。

## 代理设置

问答模型、Jev 和 MinerU 共用[网络代理](/zh/docs/preferences#网络代理)。默认跟随系统代理，也可以在 **设置 → 网络代理** 选择自定义代理或直接连接。MinerU 的测试连接、上传文件、查询进度和下载结果都使用这份配置。点击 **测试连接** 可以查看请求经过的线路。

## 连接失败时

- 认证失败：确认密钥对应当前供应商，且尚未过期。
- 模型不存在：核对准确模型 ID 与账号的可用模型。
- 地址错误：确认填写 API 地址及必要路径。
- 超时：核对网络和服务状态；问答及上下文摘要共用问答设置中的“请求超时”。摘要读取超时会有限重试；仍失败时本轮改为只保留最近内容继续回答，并在回答上方说明。可先把请求超时调至 300 秒再试，但模型服务或代理提前断开时，调大客户端时限不一定有效。详见 [问答与上下文管理](./chat)。
- 模型不会调用工具：确认模型和所用接口支持工具调用，并检查当前模型的工具绑定。

密钥保存在当前用户的应用数据目录。macOS 使用仅当前用户读写的文件权限；同一账户下的其他程序仍可能读取，因此不要把应用数据目录公开分享。详见[数据与隐私](/zh/docs/privacy)。


## MinerU 文档解析

在 **设置 → 文件设置 → 文档解析** 选择 **MinerU**，点击 **配置 MinerU**。选择 **302.AI** 或 **MinerU 官方** 后，可在下方修改**接口地址**，留空使用该供应商的默认地址。自定义地址须兼容所选供应商的接口。只改地址时，同一供应商已保存的密钥可继续使用；切换供应商时恢复对应的默认地址并使用该供应商的密钥。配置完成后，返回文件设置并点击 **保存设置**。切换到 Docling 会保留密钥。点击 **移除保存的密钥** 会立即删除当前供应商的密钥，恢复本地解析。

302.AI 与企业知识库使用同一套 MinerU 2.x 接口：默认地址为 `https://api.302ai.cn`，上传路径为 `/302/upload-file`，创建任务为 `POST /302/v2/mineru/task`，查询任务为 `GET /302/v2/mineru/task?task_id=…`。鉴权统一使用 `Authorization: Bearer <API Key>`，只填写密钥本身，不填写 `Bearer` 前缀。

302 仅解析 PDF，默认版本 **2.5**、解析方式 **自动**，可在高级参数中选择 **2.0 / 2.5** 和 **自动 / 文本 / OCR**。默认单次请求超时 60 秒、轮询间隔 2 秒、任务总时限 30 分钟；这些时限由客户端控制。其他格式走适用的内置解析器或已安装的 Docling，不自动安装组件。

![MinerU 服务商、密钥与连接测试](/images/product-mineru-cn.png)

**测试连接**使用当前填写的接口地址，不访问账户 API 日志、不上传文件、不创建任务。缺少任务参数返回 400 / 422 时仅表示接口可达，不能证明实际解析权限；401 / 403 表示该请求被拒绝。结果显示在按钮上方，实际权限以小 PDF 的完整解析为准。

302 的返回值兼容任务编号、结果下载地址、直接 Markdown，以及 JSON 字符串包裹的响应。分段 PDF 必须具有完整页码映射才发布合并结果；无法恢复页码时降级到本地解析，不截断正文。旧的两个 302 选项统一迁移为同一个配置并复用密钥。

长 PDF 在解析前按最多 **50 页一段**拆分，超过上传字节限制的分段继续缩小；每段按 MinerU、适用的内置 anydoc、已安装的 Docling 顺序独立尝试。某一段失败时只降级这一段，不会把整本 PDF 重新交给本地解析。后台增强仅尝试 MinerU 和 Docling。同一 PDF 的云分段并发跟随 MinerU 并行数设置，默认 2，可设为 1–16，并且不会超过该文档的分段数。设为 1 时逐段处理，设为 4 时单份 PDF 可同时处理最多四段。所有文档共用当前服务进程中该服务商的总并行名额；例如设为 4 时，多份文档合计最多占用四个云解析会话。云任务状态未确认时，后续分段先续查已有任务，没有可续查任务的分段转本地解析。停止本机转换后，服务商已受理的任务仍可能运行并计费。 对于能直接判定为没有文字层的扫描分段，内置解析器会立即提示需要 OCR，交给已安装的 Docling；不会自动安装组件。

成功分段正文保存在转换目录的 `.sag-pdf-parts` 中，未完成分段的云端任务记录也保留在其中。重试时复用内容和解析参数匹配的成功分段；内容或影响正文的解析参数变化会使用新的缓存。PDF 的基础文字层会先尝试单独索引；混合文字与扫描页的 PDF、纯扫描 PDF 在后台增强 OCR 和表格。全部页面都有可用文字层的 PDF 仍通过 anydoc 完成，不额外运行 Docling 增强。增强使用独立后台线程，不占用基础索引的处理线程；同一文件夹新增资料仍可先行加入基础索引。所有增强分段成功后，才按原始顺序合并并替换为完整增强正文；停止或失败不会发布不完整的增强正文，也不会覆盖已有的可用转换文件。已完成的基础文本仍可搜索，文件列表会标注等待增强、增强中或增强失败；纯扫描件需要等 OCR 提取到正文后才能搜索。合并保留原始页码范围，云端结构化结果中的页号映射回原文件。

本地多分段 PDF 在需要使用 Docling 时，会在同一份文档内复用转换进程和模型，减少每段重复启动和加载的开销。同一文档内的本地回退逐段执行，沿用当前推理线程数、OCR、表格识别和内存预算；若另一文档持有本文件所需的共享分段，闲置的本地模型可先释放内存，后续回退时按需重新加载。整份文档完成、失败或停止后即释放进程，不跨文档保留常驻模型。成功分段缓存及兼容后端回退继续生效，失败的转换进程不会用于后续分段。


拆分后的云端分段按结构化结果合并，并保留原始页码标记。页眉、页脚和页码重复出现，合并时过滤；代码块转为围栏代码并保留语言、标题和脚注；图表保留说明文字和脚注；其他带文字的类型按段落保留。遇到无法识别且没有可读文字的类型时，转换失败并提示类型与页码，随后降级到本地解析。

MinerU 官方的默认地址为 `https://mineru.net/api/v4`，使用官方 Token，可选择 VLM 或 Pipeline。两家服务不会互相复用密钥或自动切换。远程解析会发送原文档，详见[数据与隐私](/zh/docs/privacy)。

恢复 MinerU 任务时会先查询已有结果。若任务仍在排队、解析或转换，等待时限从原始提交时间计算，不会因重新索引而重置；超过配置的任务时限后转入本地解析，并在索引历史记录超时原因。任务记录继续保留，避免重复提交；服务端之后完成的结果仍可在下次索引时取回。云端排队时长由服务商决定。

## 高级运行参数

超限 PDF 使用随包提供的 QPDF 按页拆分，长 PDF 每份最多 50 页并检查上传大小；拆分支持取消，最长 120 秒。无需安装 Python。

长 PDF 分段资源位于 `.sag-pdf-parts/.sag-mineru-assets/<结果哈希>/`；其他 MinerU ZIP 结果中的图片会保存到转换目录的 `.sag-mineru-assets/<结果哈希>/`，同时保留原始 Markdown 和 content-list JSON。阅读器通过相对链接显示本地图片；索引和搜索片段保留图片描述、图注，过滤内联图片地址，模型不会因此自动获得读图能力。不同解析结果分别缓存，旧资源包不会随单篇转换正文删除。302 直接返回 Markdown 时没有可解包的图片，链接保持服务端原样。 图片描述中的嵌套或转义方括号、尖括号包裹的带空格图片路径也会改写为本地资源链接。

模型设置底部可调整失败重试次数、退避间隔和总时限。HTTP499也计入重试，总时限覆盖请求、等待和响应读取。其他分组见[运行参数](/zh/docs/preferences#运行参数)。
