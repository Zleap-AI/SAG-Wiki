## 两类模型的分工

入口：**设置 → 模型设置**。

| 配置 | 用途 | 什么时候需要 |
| --- | --- | --- |
| 问答模型（LLM） | 组织回答、调用工具、生成搜索总结 | 问答、启用自动总结的搜索 |
| 决策模型 | 判断候选原文是否提供问题所需的证据 | SAG2 深入检索、CLI 语义搜索 |

本地索引与快速搜索不需要这两类模型。只有决策模型配置也可以进行语义检索；只有问答模型无法完成依赖决策模型的 SAG2 检索。

![回答模型的供应商、地址和模型名称设置](/images/product-models-cn.png)

## 逐项填写

### 供应商

选择供应商后会填入对应接口地址。问答模型提供 OpenAI、DeepSeek、GLM、OpenRouter、302.AI 和自定义；决策模型提供 Zleap、302.AI、OpenRouter、Typesafe 和自定义。首次启动默认选择 Zleap；已有用户的服务地址和模型配置保持不变。

问答接口和决策模型判断接口是两类接口，不能只因供应商相同就互换地址。自定义服务必须兼容对应接口。

### 接口地址

填写供应商提供的 API 基础地址，而非网页聊天地址。预设地址会随供应商选项填写；使用代理或自建服务时，确认路径与服务协议一致。

问答模型默认使用 Chat Completions。需要 Responses 时，填写完整接口地址（如 `https://api.openai.com/v1/responses`，代理服务则使用其对应地址）。该地址启用 Responses 流式回答、工具调用与推理状态回传；思考强度使用 `reasoning.effort`，界面的“极高”对应 `max`。GPT-6 Astra 与 GPT-6.1 Sol 不提供关闭推理档位。支持的档位由实际模型与服务决定，不支持时请恢复默认或选择服务支持的档位。仅填写 `/v1` 仍使用原来的 Chat Completions 接口。

切换到不同服务来源后，需要填写新供应商的 API Key。应用不会把原供应商密钥直接用于新的来源。

决策模型可填写基础地址（如 `http://127.0.0.1:8000/v1`），也可填写完整的 `/systemone` 或 `/decisions` 接口地址，程序不会重复追加接口路径。

### 决策模型鉴权方式

- **API Key**：用于需要密钥的服务，保留已有配置的默认方式。
- **无需鉴权**：用于不要求密钥的本地决策模型服务。此模式不发送鉴权头，保存后移除已存储的决策模型密钥。

服务需兼容决策模型判断接口。CLI 对应命令为 `sag config --url http://127.0.0.1:8000/v1 --model YOUR_MODEL --auth none`；切回密钥服务使用 `--auth bearer --key-stdin`。

### 可选模型与模型名称

问答模型的 **可选模型 · 每行一个** 决定界面里可以切换哪些模型。每行填写一个服务支持的准确模型 ID，不加逗号；去重后保存。连接测试使用列表第一项。

决策模型的 **模型名称** 填写一个决策模型 ID。首次默认使用 Zleap 开放平台的 `Zev-1`，切换到 Zleap 时也会自动填入 `Zev-1`。基础地址为 `https://api.zleap.com/v1`，实际请求 `/v1/systemone`，使用 API Key 鉴权。参见[决策模型文档](https://platform.zleap.com/docs/decision)。切换到其他供应商后，请核对模型名称是否受该服务支持。

<Callout title="推广">
[Zleap 开放平台](https://platform.zleap.com)现已提供自研和自部署的决策模型 **Zev-1**，全方位优于 Jev 模型，欢迎大家试用。
</Callout>

### API 密钥

选择 Zleap 时，点击 **获取 API Key** 打开[开放平台控制台](https://platform.zleap.com/console)，创建并填写该平台的密钥。Zleap 决策模型与 302.AI 问答模型的密钥分别配置。

粘贴对应服务的密钥。输入框默认隐藏，可点击显示或隐藏；已保存时留空会保留原密钥。“移除保存的密钥”会立即删除对应密钥。

两类服务都选择 302.AI 时，填写一个密钥可以自动填入尚未配置的另一项。保存前仍需确认两项服务与密钥都正确。

### 测试连接

分别点击两张配置卡片里的 **测试连接**，检查接口、模型和密钥是否可用。测试成功后点击底部 **保存设置**。测试可能发送验证请求，按供应商规则计费。
问答模型测试会请求一条简短回复；输出长度由模型服务的默认设置控制。

![决策模型的独立配置与连接测试入口](/images/product-jev-cn.png)

## 推荐配置顺序

1. 先配置决策模型并测试，保存后运行一次深入搜索。
2. 再配置支持工具调用的问答模型并测试。
3. 保存后在问答页选择模型，提问并检查引用来源。
4. 需要调整提示词、思考强度或工具权限时，进入[问答设置](/zh/docs/chat#问答设置详解)。

## 连接失败时

- 认证失败：确认密钥对应当前供应商，且尚未过期。
- 模型不存在：核对准确模型 ID 与账号的可用模型。
- 地址错误：确认填写 API 地址及必要路径。
- 超时：核对网络和服务状态；问答及上下文摘要共用问答设置中的“请求超时”。摘要读取超时会有限重试；仍失败时可先调至 300 秒再试，但模型服务或代理提前断开时，调大客户端时限不一定有效。详见 [问答与上下文管理](./chat)。
- 模型不会调用工具：确认模型和所用接口支持工具调用，并检查当前模型的工具绑定。

密钥保存在当前用户的应用数据目录。macOS 使用仅当前用户读写的文件权限；同一账户下的其他程序仍可能读取，因此不要把应用数据目录公开分享。详见[数据与隐私](/zh/docs/privacy)。


## MinerU 文档解析

入口：**设置 → 模型设置 → 文档解析 · MinerU**。服务商仅有 **302.AI** 和 **MinerU 官方**。保存对应 API Key / Token 后自动优先使用 MinerU；清除密钥后恢复本地解析。

302.AI 与企业知识库使用同一套 MinerU 2.x 接口：Base URL 为 `https://api.302ai.cn`，上传路径为 `/302/upload-file`，创建任务为 `POST /302/v2/mineru/task`，查询任务为 `GET /302/v2/mineru/task?task_id=…`。鉴权统一使用 `Authorization: Bearer <API Key>`，只填写密钥本身，不填写 `Bearer` 前缀。

302 仅解析 PDF，默认版本 **2.5**、解析方式 **自动**，可在高级参数中选择 **2.0 / 2.5** 和 **自动 / 文本 / OCR**。默认单次请求超时 60 秒、轮询间隔 2 秒、任务总时限 30 分钟；这些时限由客户端控制。其他格式走适用的内置解析器或已安装的 Docling，不自动安装组件。

![MinerU 服务商、密钥与连接测试](/images/product-mineru-cn.png)

**测试连接**只检查所选解析接口，不访问账户 API 日志、不上传文件、不创建任务。缺少任务参数返回 400 / 422 时仅表示接口可达，不能证明实际解析权限；401 / 403 表示该请求被拒绝。结果显示在按钮旁，实际权限以小 PDF 的完整解析为准。

302 的返回值兼容任务编号、结果下载地址、直接 Markdown，以及 JSON 字符串包裹的响应。分段 PDF 必须具有完整页码映射才发布合并结果；无法恢复页码时降级到本地解析，不截断正文。旧的两个 302 选项统一迁移为同一个配置并复用密钥。

拆分后的分段按结构化结果合并，并保留原始页码标记。页眉、页脚和页码重复出现，合并时过滤；代码块转为围栏代码并保留语言、标题和脚注；图表保留说明文字和脚注；其他带文字的类型按段落保留。遇到无法识别且没有可读文字的类型时，转换失败并提示类型与页码，随后降级到本地解析。

MinerU 官方继续使用 `https://mineru.net/api/v4` 和官方 Token；其 VLM / Pipeline 等识别选项保持独立。两家服务不会互相复用密钥或自动切换。远程解析会发送原文档，详见[数据与隐私](/zh/docs/privacy)。

## 高级运行参数

模型设置底部可调整失败重试次数、退避间隔和总时限。HTTP499也计入重试，总时限覆盖请求、等待和响应读取。其他分组见[运行参数](/zh/docs/preferences#运行参数)。
