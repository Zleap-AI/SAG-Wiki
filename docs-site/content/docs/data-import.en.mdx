On desktop, click **+** in the sidebar, switch from **Add folder** to **Import data**, then choose a source. You can also right-click an empty area of the **Indexed files** overview and choose **Import data**, or open **Settings → Data import**.

![Import data in the Add folder dialog](/images/product-add-data-en.png)

## Import notes

Click **Import notes** next to the source. To import a Notion ZIP, use **Notion → Configure → Import from an export file**.

| Source | Input |
| --- | --- |
| Notion | Export HTML with subpages included and select the ZIP. Markdown and CSV exports are not supported. |
| Evernote | Select ENEX exports. Multiple notebooks can be selected together. |
| Google Keep | Export Keep with Google Takeout and select the ZIP. Archived notes are included by default; this can be turned off. Deleted notes are excluded. |
| Apple Notes | macOS only. Read notes downloaded to this Mac and choose the folders to import. |

Notes are converted to Markdown with supported formatting, internal links and attachments. The default destination is `sag-wiki/notes/Source/` inside your system Documents folder. Click **Change** to choose a destination for this import. Sources are grouped in Notion, Evernote, Google Keep and Apple Notes folders. Imports share the source folder without dated subfolders. Existing notes are skipped and identical attachments are reused without overwriting existing content. Completed imports are added to the library and indexed automatically.

Apple Notes is read through a read-only database snapshot. If macOS denies access, the importer shows a permission guide. Click **Open System Settings**, then enable the current app in **Privacy & Security → Full Disk Access**. Returning to the app checks access again; you can also click **Check again**. Restart if macOS asks you to. For preview builds, enable **SAG Wiki Preview**. Alternatively, use **Choose data folder** to select a copy containing `NoteStore.sqlite` and its attachment directories. Unlock locked notes in Apple Notes first. Attachments that have not been downloaded locally cannot be imported.

The result lists note and attachment counts and explains any skipped or failed items. If every note fails to convert, the result shows a failure and does not save empty placeholder notes. Successfully converted items can still be imported. The feature reads local files, does not connect to source accounts or call a model, and does not continuously sync.

![Import notes from an export file](/images/product-note-import-en.png)

## Import chats

Select **Import chat history** beside **Claude Code** or **Codex** to convert local conversations to Markdown and add them to the knowledge base.

1. The dialog shows chats from the selected source. The app reads its default local transcript folder. To use another folder, enter its path and click **Load**.
2. Filter by project or search titles across all records. The list shows 50 chats per page. Selections remain when changing pages; **Select this page** affects only the current page. The first chat is previewed automatically without being selected.

   Codex reads its local session catalog first and loads complete transcripts only for preview or import. Without a compatible session catalog, list information is read from transcript files.
Chat titles use the existing name when available, or the first actual question when the name is empty or contains only system information. Attachment metadata is excluded from titles; image-only chats use “图片对话 · date”. Long titles are shortened visually in the list and kept in full in previews and exports. Internal side-conversation boundary instructions are excluded.

3. **Show tool calls and results** is off by default: previews and imports contain only questions and answers. Turn it on to show tool arguments and results, including when switching chats, and include them in imports without a fixed-length truncation. System prompts, environment and page context, internal notifications, continuation summaries, thinking and automatically injected Skill bodies are excluded. User questions, answers, Skill references and code examples are retained; structured question replies keep only the question and selected answer.
4. Click **Import**. Chats are saved automatically to **Documents/sag-wiki/agent-history** under **codex** and **claude code** subfolders and added to the knowledge base. The save location displays the current source subfolder. Folders are created on first import. Both interface languages use this folder name. Choose **Change** beside the location to select another folder. SAG remembers it for future imports; existing files stay in their original location.

![Selecting and previewing chats with tool calls off by default](/images/product-chat-import-en.png)

Each chat becomes one Markdown file. Importing again skips unchanged content and updates the same file with new content. If you have edited the imported file, a conflict is reported and your changes are preserved. Embedded images are saved in the adjacent `chat-assets/` folder. External image links are retained and follow the reader's policy of not loading external images automatically.

Supported inputs include Claude Code JSONL transcripts and cross-file continuations, plus plain and `.jsonl.zst` compressed Codex transcripts. Multiple files for the same Codex session are merged. Damaged, incomplete or missing continuation records show an error; correct the source or wait for the chat to finish, then reload. Original transcripts stay unchanged. Import does not call a model. Chat import is available on desktop.

### Scheduled imports

Select **Import chat history** beside **Claude Code** or **Codex**. With **Scheduled sync** off, chats are imported manually. Turn it on at the bottom of the dialog to choose **Every 30 minutes**, **Hourly**, **Every 6 hours**, **Every 12 hours**, or **Daily**. Choose **Daily** to set a specific time. Each source has its own schedule, and changes are saved automatically. Scheduled imports use the transcript folder and **Show tool calls and results** setting in the same dialog. To change the source folder, enter a new path and select **Load**.

![Set the daily import time for Codex](/images/product-chat-import-schedule-en.png)

Intervals are measured from when the schedule was enabled, its frequency changed, or it last ran. **Daily** uses the local time of the computer running SAG. When the background service resumes, an overdue interval schedule runs once and a daily schedule can catch up on the same day. Each run processes sessions in that source folder and uses the same destination and subfolders as manual imports. Unchanged sessions are skipped, new content updates the original Markdown file, and manually edited files are kept. Hover over the schedule controls to see the last run result.

## Receive a share

The Add folder window has a separate **Receive share** tab where you can enter a share code and choose the save location. **Settings → Data import → Share** provides the default folder and clipboard preferences. Clipboard code detection is enabled by default. You can turn it off or change the download folder here. The default folder is `sag-wiki/share` inside your system Documents folder. Folder and detection changes are saved immediately. See [sharing and receiving](/en/docs/file-sharing).

## Connect online sources

On desktop, open **Settings → Data import** and find **Online sources** above **Share**. Click the clock next to the source name or choose **Configure**. Click **Setup guide** next to the dialog title for instructions for the current source. Go back to continue where you left off. Check each connection to see whether scheduled sync is enabled.

![Online sources and scheduled sync in Data import](/images/product-online-import-en.png)

### Feishu [#feishu]

1. Create or open a **Custom App** in the [Feishu Developer Console](https://open.feishu.cn/app). Copy the permissions JSON below for Knowledge base or Drive.
2. Go to **Development Configuration → Permissions & Scopes**. Open **Batch import/export scopes** from the menu next to **Add scopes** (批量处理), paste the JSON in the **Import** tab, and confirm the permissions appear under **User scopes**.
3. In **Security Settings → Redirect URLs**, add `http://127.0.0.1:24682/feishu/oauth/callback`. Make the app available to the account that will sign in, then publish it under **Version Management & Release** and wait for any required approval.
4. Copy the App ID and App Secret from **Credentials & Basic Info**. In **Settings → Data import → Feishu**, choose the import type, enter the credentials, and select **Authorize with Feishu**. After authorizing, return to SAG, select what to import, and click **Save and import**.

If scheduled sync pauses because the monthly quota is exhausted, click **Sync now** once the quota is available again.

#### Knowledge base [#feishu-wiki]

Selecting a page also imports its subpages that you can read.

```json
{
  "scopes": {
    "tenant": [],
    "user": [
      "wiki:space:retrieve",
      "wiki:node:retrieve",
      "wiki:node:read",
      "docx:document:readonly",
      "drive:drive:readonly",
      "drive:export:readonly",
      "offline_access"
    ]
  }
}
```

### Lark [#lark]

1. Create or open a **Custom App** in the [Lark Developer Console](https://open.larksuite.com/app). Copy the permissions JSON below for your import type.
2. In **Permissions & Scopes → Batch import/export → Import**, paste the JSON and confirm the permissions appear under **User scopes**.
3. In **Security Settings → Redirect URLs**, add `http://127.0.0.1:24682/lark/oauth/callback`. Enable user token refresh if the option appears. Make the app available to the account that will sign in, then publish it.
4. In **SAG → Data import → Lark**, choose the import type, enter the App ID and App Secret, and select **Authorize with Lark**. After authorizing, choose what to import and how often to sync, then select **Save and import**.

### Notion [#notion]

1. In [Notion integrations](https://www.notion.so/my-integrations), create an **internal integration** for the target workspace. Enable **Read content** and copy the integration's API token. [Notion connection guide](https://www.notion.com/en-gb/help/create-integrations-with-the-notion-api)
2. On the Notion page to import, open **⋯ → Connections** and add the integration. In **SAG → Notion → Configure → Add connection**, enter the connection name and token and click **Test connection**.
3. Select the authorized pages and click **Save and import**. SAG saves supported Markdown and attachments. If the page is incomplete, the error appears in sync history and the last complete copy is preserved. Use **Import from an export file** for a Notion ZIP.

### Yuque [#yuque]

1. Create an API token in [Yuque token settings](https://www.yuque.com/settings/tokens) using an account with read access to the target personal or team book. If the option is unavailable, check the account's API access.
2. In **SAG → Yuque → Configure**, enter the connection name and token. Click **Test connection** and choose the book. For a team book, expand the relevant team first.
3. Click **Save and import**. Check the documents and folder structure at the save location and review any failures in **Sync history**.

### RSS / Atom [#rss]

1. When you add a connection in **SAG → RSS / Atom → Configure**, the address defaults to the [Chinese Zleap Blog feed](https://zleap.com/blog/rss.xml) in Chinese interfaces and the [English feed](https://zleap.com/en/blog/rss.xml) in other languages. You can replace the address with any public RSS or Atom feed, then click **Test connection**.
2. Check the feed name and destination and click **Save and import**. Files include the original link and the body or a labeled summary from the feed.

### Scheduled sync [#scheduled-sync]

Set a frequency for each connection. Choose **Manual only**, **Every 30 minutes**, **Hourly**, **Every 6 hours**, **Every 12 hours**, or **Daily**. For daily sync, choose the time in your local time zone.

1. Finish an initial import with **Manual only**. Add an item to the test source or edit a document that was already imported.
2. Open the connection's **Configure → Sync schedule**, select **Daily**, and set a time a few minutes ahead in your local time zone. Save and check **Next sync** on the connection.
3. Keep the computer and the background service running. After the scheduled time, open **Sync history** to check for a new run and confirm the new or updated file at its save location. You can close the window while the background service continues to run.

You can pause the schedule per connection and still use **Sync now**. Each connection runs at most once to catch up after the service resumes.

Files go into `sag-wiki/data-sources/<platform>/<connection>/` in the system Documents folder by default. Change the destination when adding the connection. Saved files are indexed. Sync skips unchanged items and preserves local edits when there is a conflict; failed items can be retried. Removing a connection or deleting content at the source leaves local copies intact. SAG does not write changes back to the provider.
