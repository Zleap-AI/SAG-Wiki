## Start a conversation

Open Q&A and send your question. Type `@` to select a file. The scope selector controls which documents can be retrieved.

The sidebar shows folder management and the file tree. The Q&A home shows the welcome area, composer and conversation list. To add files, select **+** next to **Folder management** in the sidebar.

The desktop Q&A icon plays a short random animation when idle or when you hover over it. It follows your system's Reduce Motion setting.

![Q&A home with conversation history and the folder sidebar](/images/product-ask-home-en.png)

![An answer with citations](/images/product-chat-en.png)

During generation, reasoning, intermediate text and tool calls appear in order. When the final answer starts, the details collapse, leaving only an elapsed-time row and a divider above the answer. Select the row to expand the details again.

If the local service connection temporarily fails, the app reports the error and keeps reconnecting. New questions continue to show streamed text and tool progress after the connection recovers.

![Processing details collapsed above the final answer](/images/product-answer-process-en.png)

## SAG Wiki Assistant

The assistant home lists and searches assistant conversations. Switch back to your files to view and search knowledge-base conversations on the Q&A home.

On the Q&A home, click **SAG Wiki Assistant** below the question box. The box shows a suggested question. When the box is empty, press Enter to send the suggestion or Tab to fill it in for editing.

The assistant uses SAG2 to search the bundled user guides and the Chinese and English changelogs. You can ask “What changed in 0.4.0?” When an answer model is configured, it calls `sag2_search` to find passages and can search again for missing evidence. The assistant streams its answers. Without an answer model, the app runs SAG2 and shows the relevant passages directly. When Jev is configured, it judges which passages provide relevant evidence. Otherwise, SAG2 ranks the passages and expands the search locally.

Click the question mark in the lower-left corner to open the online documentation in the current interface language.

The bundled changelogs are in Simplified Chinese and English. The assistant can also consult the English changelog in other interface languages. Links within the changelog open the corresponding pages on the official site.

Click a citation number to open the full document in the app's right panel at the cited section. On the assistant home, click **Back to my files** below the question box to return to the Q&A home. From an assistant conversation, click the back arrow in the upper-left corner to return to the assistant conversation list.

## Research steps

Expand the processing summary to inspect grouped searches, document reads and tool timings.

![Expanded research steps](/images/product-research-steps-en.png)

While content is being generated, the page follows the latest output, including the transition from retrieval to the answer. Scrolling up with a mouse wheel or trackpad pauses following and preserves your reading position. Scrolling back to the bottom resumes following.

Answers display Markdown headings, tables, block quotes, ordered and unordered lists, task lists, links and code blocks. Wide tables and code blocks scroll horizontally, and citation numbers remain clickable.

![Markdown tables, quotes and lists in answers](/images/product-answer-markdown-en.png)

Code blocks marked `mermaid` in answers are rendered locally as diagrams. Invalid syntax keeps the source visible and displays an error. See [Mermaid diagrams](/en/docs/files#mermaid-diagrams) for supported types and an example.

Mathematical formulas in answers are rendered locally: inline with `$…$` or `\(…\)`, display with `$$…$$` or `\[…\]`. Currency amounts, `$HOME`-style text, code spans and code blocks stay literal; a formula that cannot be parsed shows an error and keeps its source for copying. The reader view for knowledge-base documents renders formulas the same way. Superscripts and subscripts kept by document conversion display as such; a PDF formula becomes TeX only when the parser supplies LaTeX, for example with MinerU formula recognition enabled.

Fonts used for formula rendering are bundled with the app and remain available offline; no CDN is used.

Isolated script fragments wrapped in `$…$` (such as `$_{0}$` in `V$_{0}$`) stay literal. Leading scripts followed by a base (such as `$_{2}^{3}He$`) and escaped underscores (such as `$x\_$`) still render as formulas.

For commands or paths containing multiple `$` characters, use inline code, such as `$HOME/$USER`, to keep the text literal.

## Open a citation

Click a citation number to open the full document in the side panel, automatically positioned at and highlighting the referenced passage. HTML and Markdown are supported.

The file path appears in gray below the file name. Long paths are truncated; hover over the path to see it in full.

![Source document opened from a citation](/images/product-citation-en.png)

Citations help you verify the answer. Read the surrounding context when information is incomplete or contradictory. If you open the standalone document view, Back returns to the conversation.

## Save as a note

After an answer finishes, click **Save as note** below it to store the answer as a Markdown file inside your knowledge base. The first save opens a panel: the file name comes from the question, and the default location is Documents / sag-wiki / notes, created and added to the library when missing. You can pick any other registered folder and check **Remember this location**. Turn off **Ask for a location every time** under **Settings → Chat settings → Notes** to save directly to the remembered folder. Hold Option (macOS) or Alt (Windows) while clicking Save to reopen the panel. You can also change the default folder in that settings group.

The top of the note records the question, time, model, scope, and for each citation the file path, file hash, byte and line range, and the passage as it was when saved. The body is the answer itself; only sources the prose actually cites are kept and renumbered in order of first use, followed by a Sources list. This metadata travels with the note. After copying or syncing it, the source paths must still resolve and the sources must be registered in the current knowledge base.

## Verify citations

When you open a note, the editor shows its status above the text. Each citation is judged against the current file content:

| State | Meaning |
| --- | --- |
| Intact | The source file is unchanged |
| Moved | The file changed, but the cited passage appears whole at a new position; line numbers update automatically |
| Changed | The cited passage was edited; a word-level comparison of the saved and current text is available |
| Missing | The file was deleted, or no similar passage exists in it anymore |
| Unverified | The source is outside the knowledge base, unreadable, or the note's header could not be parsed |

States update whenever a source file is indexed or removed; **Check again** verifies immediately against the files on disk. Expanding the citation list lets you open the source, view the comparison or the saved text, and **Ask again** starts a new conversation with the note's question and scope. In the file list, notes carry a status dot, folders show how many notes need attention, and the filter can show only notes to review. Verification never calls a model.

## Manage conversations

Open history from the conversation list on the Q&A home. Use its search button to search titles and answers. Inside a conversation, the top back arrow returns to the list and lets you start a new question without removing history. The back button is disabled during generation; stop generation first. The sidebar always displays folders.

History that has not yet been summarized includes previous questions, final answers and compact tool records. Earlier tool use is replayed in the model API's native shape, as tool-call and tool-result messages: each record keeps its name, arguments, status and the first 500 characters of its result, and the final answer follows as plain text. Reasoning and intermediate text are excluded from the next turn. The model therefore has no internal record format to imitate in its own answers. If the model service rejects this replay shape (HTTP 400 or 422), the app resends the same records once as plain text appended to the earlier answer. The full record remains available in the interface.

A model may still wrap a final answer in a JSON object with an answer field. When the object has only the answer, sources and tool_history fields, the app unwraps the text before checking citations and shows only the text; the sources list of IDs becomes checkable citation labels. Other JSON structures the user asked for are kept as they are.

The app checks the context budget before each model request, including during tool use. When content approaches the budget, compaction starts early and leaves headroom; the current answer model produces a summary covering the task, user constraints, confirmed facts and evidence, completed work, remaining questions and next steps. That summary replaces older content. The most recent exchange and complete tool call are retained when space permits.

Very long histories are summarized in bounded batches and merged. Each batch holds at most 32,768 tokens and never more than the answer context budget, so the default 65,536 budget usually needs one or two batches. Summaries prefer the no-reasoning mode in supported model profiles and set an output cap for models with known support; other compatible endpoints are not forced to accept those parameters. Summary length is judged by the smaller of the provider's reported output tokens and a local estimate, so reasoning tokens are not counted; only the local estimate is used when the provider reports none. The completed summary is saved with the conversation for later turns. Summarization makes additional model requests without counting as tool calls.

Connection failures, retryable HTTP errors, response body timeouts and incomplete summary streams are retried within the model retry count, backoff and total time limit in advanced runtime settings. The first retry repeats the current batch; consecutive failures reduce its size. Successful batches are retained within the same running compaction task, so retries do not restart the entire summary or repeat tool operations. Progress shows the current batch, the estimated total and retries, for example "Summarizing context: part 2 of 3". Cancellation stops waiting and retries. Recovery checkpoints are held only in the running task, not across app restarts or manually restarted Q&A requests.

If retries fail, the turn no longer fails as a whole. The app continues with only the latest exchange, this turn's tool records and the current question, and keeps any summary generated earlier together with the notice. A notice above the answer says the context summary could not be generated, with the reason available on demand, and the answer statistics line shows how many earlier exchanges were omitted. This fallback is not saved as a summary, so the next turn tries a model summary again. Incomplete summaries are never used for subsequent answers. Full questions, answers, tool records and source passages remain stored locally and are not overwritten by the summary.

Requests keep the system prompt first, including retries after citation checks, empty-answer checks, and tool-limit reminders. Tool results and citation IDs remain intact.

When the model's final reply contains only whitespace, the app asks it to answer once more. If the reply is still empty, the turn is reported as failed with "The model returned no answer text" instead of being marked complete. Empty answers already stored in history show a placeholder with a regenerate action. If one answer fails to render as Markdown, that answer falls back to plain text without affecting the others.

Within one turn, consecutive SAG tool calls with identical arguments run twice as usual. The third consecutive call is not executed and returns a note that the result would not change; the record is marked "Skipped" and does not count toward the call limit. A fourth consecutive call ends tool use for the turn, and the model answers from the evidence it has. A different call in between restarts the count. If the model service ignores the stop request and keeps calling, the turn ends with a note that the model kept repeating the same call, plus the list of material gathered, instead of waiting indefinitely. External MCP tools may have side effects and are not subject to this check. When the model calls a tool that is not currently bound, for example one used in an earlier turn and disabled since, the app returns "tool not enabled" as that call's result and continues the turn instead of failing it.

## Configure an answer model

Enter your provider endpoint, model and API key in settings. Configure Jev as well for semantic retrieval. Jev finds evidence; the answer model composes the response.

## Cross-language sources

Q&A instructs the model to include equivalent Chinese and English wording in the same natural-language search, preserving the original constraints. This helps Chinese questions retrieve English sources. Chinese questions receive Chinese answers by default; you can request a different answer language in your question.

This behavior is guided by the Q&A prompt. Expand the processing details to inspect the actual query, and open citations to check the English source. Exact text, code and file paths do not need translation.

The Search page and standalone MCP calls continue to search the supplied query. When using a third-party MCP client, that client determines the query language.

## Q&A settings in detail

Location: **Settings → Q&A settings**. Select the answer model you want to configure first.

![Reasoning effort and system prompt per model](/images/product-chat-settings-en.png)

### Settings saved per model

| Setting | Purpose | Notes |
| --- | --- | --- |
| Reasoning effort | Choose a supported reasoning level | Options depend on the model and service. Higher effort usually takes longer; use Default when unsupported. |
| System prompt | Specify role, language, style or task requirements | Applies only to the selected model. Blank uses the built-in prompt; clear it to restore that prompt. |
| Built-in SAG tools | Allow local search, reading, matching, time and calculations | Disable the group or individual tools. Semantic search also requires Jev. |
| External MCP bindings | Select external servers and tools for the model | Connection details are shared; bindings and enabled tools are per model. |

Use the reasoning options actually shown by the UI. Some models offer Off, Low, Medium, High or Max. Unsupported means the specific model/service combination has no mapped reasoning parameter; it does not mean the model is unusable. Restore Default in that case.

A system prompt does not replace connection settings or add tool support to an incompatible model. See [MCP and tool bindings](/en/docs/mcp) for setup, testing and confirmations.

### Request settings shared by all models

| Setting | Default / range | Effect |
| --- | --- | --- |
| Tool calls per turn | 20 / 0–100 | The default is 20. Values from 1 to 100 cap the total SAG and external MCP calls during one Q&A turn; skipped repeats do not count. 0 means unlimited. At that limit, the model answers from available results and identifies what remains unconfirmed. A saved value of 0 stays unlimited. |
| Answer context budget (tokens) | 65536 / minimum 4096 | Controls input including the question, history, tool records and citations. No fixed maximum; set it within the model's actual capacity. History or material may be reduced to fit. |
| Request timeout | 120 seconds / 10–600 seconds | Applies to each answer or summary model request, including response body reads, rather than the entire Q&A turn. A short timeout can interrupt slow models; a long one delays failure feedback. |

The context budget is not an output-length setting; output length is controlled by the model service. Entering a value beyond the provider limit does not expand model capacity and may cause failure.

The tool-call limit differs from SAG2 expansion rounds. One `search` call can contain several retrieval rounds and Jev requests.

### Save and verify

After saving, send a new question and check the selected model, tool calls and citations. When changing models, verify that model's prompt, reasoning and tools instead of assuming it inherits the previous model's configuration.

If the notice above an answer says the context summary could not be generated and the reason is a timeout, try increasing Request timeout to 300 seconds (up to 600) and retry. This can help when the client deadline is too short; it cannot guarantee recovery from an earlier model-service or proxy disconnection. Each summary batch, including its retries, backoff and response body reads, is bounded by Model request total time limit in advanced runtime settings.
