## 使用方式

Linux（Ubuntu 24.04、Debian 12，x86_64 / ARM64）只需安装独立 CLI，即可运行 HTTP API，无需桌面端或图形界面。API 与桌面端、CLI 共用知识库、索引和决策模型配置。默认允许本机和局域网连接。

API 提供搜索、文件夹浏览和服务状态查询。检索结果按原文片段返回，不生成问答或总结。具体参数、响应和错误码见 [API 文档](/zh/docs/api)。

通过 MCP 客户端接入知识库，请阅读 [MCP 说明](/zh/docs/mcp-guide)。

## 开启服务

macOS、Windows 和 Linux 均可运行 API 服务，供本机和局域网中的程序调用。

已安装桌面端时，在 **设置 → 远程服务** 中点击 **创建 Key**，再打开 **API 和 MCP**。API 可单独启停。

通过独立 CLI 开启时，先安装 Node.js/npm，再运行以下命令。本页命令示例使用 macOS/Linux 终端语法，目录替换为运行服务的电脑上的实际完整路径。Windows 可在 PowerShell 中运行相同的 `sag` 命令，使用 Windows 完整路径。

```sh
npm install -g @zleap-ai/sag

sag config
sag add "/data/资料"
sag api key create --name "业务程序A"
sag api start
```

`sag config` 配置深入检索使用的决策模型。`sag api key create` 创建其他程序调用 HTTP API 所用的密钥，两种密钥分别管理。快速搜索无需配置决策模型。

新建的 API Key 保存在本机，可在桌面端的 Key 列表中再次复制。旧版本创建的 Key 仍可使用；如需从设置中复制，请创建新 Key。每个 Key 都可搜索全部知识库，可单独撤销。

## 发起搜索

将地址替换为运行服务的电脑地址，Key 替换为创建时保存的值。默认端口为 `24681`，实际地址以 CLI 输出或 **设置 → 远程服务** 显示的内容为准。

```sh
export SAG_API_URL='http://192.168.1.10:24681'
export SAG_API_KEY='<API_KEY>'

curl --fail-with-body --max-time 65 \
  -H "Authorization: Bearer $SAG_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"query":"项目如何部署","mode":"deep","limit":10}' \
  "$SAG_API_URL/v1/search"
```

| 模式 | 用途 | 整次请求时限 |
| --- | --- | --- |
| `deep`，默认 | 用完整问题检索相关证据，需要决策模型 | 60 秒 |
| `fast` | 在本地索引中查找关键词，无需模型 | 30 秒 |

接口同步返回结果，时限包含排队和执行。客户端超时可以略高于服务端时限，为网络传输留出时间。深入检索失败会明确报错，保持所选模式。

## 选择搜索目录

先请求 `GET /v1/folders` 列出所有已导入的根文件夹。传入 `path` 时，列出该目录的直接子文件夹，按层级浏览。

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $SAG_API_KEY" \
  "$SAG_API_URL/v1/folders"

curl --fail-with-body --get \
  -H "Authorization: Bearer $SAG_API_KEY" \
  --data-urlencode 'path=/data/资料' \
  "$SAG_API_URL/v1/folders"
```

将返回的完整路径放入搜索请求的 `paths` 数组，可以选择一个或多个根目录、子目录。不传 `paths` 或传空数组时搜索全部知识库。路径属于服务端电脑；同名文件夹通过完整路径区分。

```json
{
  "query": "项目如何部署",
  "mode": "deep",
  "paths": ["/data/项目资料", "/data/技术文档/部署指南"],
  "limit": 10
}
```

## 启停与 Key 管理

| 命令 | 作用 |
| --- | --- |
| `sag api start` | 开启 API，并保存启用状态 |
| `sag api start --host HOST --port PORT` | 按指定 IP 地址和端口开启 |
| `sag api status --json` | 输出状态和地址 JSON，不显示密钥或启动后台 |
| `sag api stop` | 关闭 API，取消 API 搜索，保留共享后台 |
| `sag api status` | 查看运行状态及本机和局域网的 API、MCP 地址 |
| `sag api mcp config` | 导出含地址和 Key 的配置，选项见 [MCP 说明](/zh/docs/mcp-guide) |
| `sag api key create --name NAME` | 创建并显示完整 Key |
| `sag api key list` | 查看 Key 名称、ID 和部分标识 |
| `sag api key revoke KEY_ID` | 撤销 Key，取消该 Key 的搜索 |
| `sag api autostart enable` | 开启平台自启机制 |
| `sag api autostart disable` | 关闭平台自启机制 |
| `sag api autostart status` | 查看自启注册状态 |

没有有效 Key 时，API 保持运行，HTTP 请求返回 `401 未授权`。撤销最后一个 Key 也不自动关闭 API。管理操作通过本机 CLI 或桌面设置执行，HTTP 不提供管理接口。

## 后台运行与桌面设置

关闭终端后，服务继续运行。桌面端 **设置 → 远程服务** 仅在 API 运行时显示本机和局域网的 API 与 MCP 地址，可复制 API 地址或 MCP 配置。绿色状态点表示服务正在运行；标题右侧的 **API 文档** 打开接口参考页。
展开 **API 和 MCP** 板块底部的 **调用示例**，可查看和复制请求命令。

**API 和 MCP** 下方的 **连接配置** 始终显示，可选择 **仅本机** 或 **本机与局域网**（默认）。两种服务共用此设置，修改前需关闭网页服务和 API。保存并启动后，选择 **仅本机** 只显示本机地址；选择 **本机与局域网** 还会列出可用的局域网地址。启停、Key 和自启操作即时生效。

打开桌面端时按已保存的 API 启用状态恢复；手动停止后，再打开桌面端仍保持关闭。**开机自启** 位于连接配置下方的独立板块，默认关闭。开启后，Linux 无需登录即可运行；macOS、Windows 在用户登录后启动。

API 与桌面端、CLI 共享现有的 20 个耗时任务额度，满额后等待。索引尚未完成时，可以搜索已有内容。HTTP 默认关闭浏览器跨域访问，普通本机和局域网程序不受影响。

继续阅读 [API 文档](/zh/docs/api)，查看完整接口约定。
