## 添加与索引

在侧栏中，在“文件夹管理”中添加目录。SAG Wiki 根据文件类型设置和忽略规则建立索引，后续文件变更会触发增量更新。索引在后台进行：添加大文件夹时窗口立即返回，进度显示在侧栏底部，期间可正常使用搜索和问答。 准备文件监听期间会显示准备状态，大文件夹可能耗时数分钟；完成挂载后开始扫描文件。 如果文件监听挂载失败，扫描仍会继续，完成后保留“自动更新受限”的错误详情；可在索引设置中重建索引重试。显式重新添加文件夹会先重置旧监听，再重新挂载。 目录恢复后，新产生的文件变动仍会自动更新索引。

Markdown、普通文本、RTF、Word、PowerPoint、Excel、OpenDocument、CSV、EPUB 和文本型 PDF 默认启用。Office、RTF、表格、电子书与 PDF 由内置 anydoc 在本地解析，无需下载组件。代码和配置文件按文件类型开关启用。扫描 PDF 和其他格式可按需安装 Docling。

![示例文件夹完成索引后的文件总览](/images/product-folders-cn.png)

## 限制搜索范围

只添加需要使用的目录。问答与搜索的范围选择独立于当前正在浏览的文件夹；浏览目录不会自动改变查询范围。

## 忽略文件

项目根目录和子目录中的 `.gitignore` 与 `.sagignore` 均会生效。`.sagignore` 的优先级更高。

```text
node_modules/
dist/
.env
**/*.generated.md
```

不要把不希望检索或发送给模型服务的敏感文件纳入索引。修改规则后，可检查索引状态确认范围。

## 移除与清理

从文件夹管理移除目录会清理接入关系和索引，原文件保留。移除子目录会保存排除状态；再次添加相同子目录可以恢复。

设置中的清除文件用于清理知识库索引。会话记录与文件索引分别管理，操作前请阅读界面说明。

## 通过 CLI 检查

```sh
sag list
sag check
sag add --types md,txt,html,py,js,ts,tsx,json,yaml
```

`--types` 选择该目录要索引的文本或内置文档类型，例如 `md,docx,pdf,xlsx`。索引尚未就绪时，等待完成后再搜索。

## 文件设置详解

入口：**设置 → 文件设置**。全局设置用于没有单独配置的文件夹。文件类型、排除目录或切分设置改变后，先保存；再根据状态确认索引完成。

### 导入文件类型

| 选项 | 包含内容 | 默认状态 |
| --- | --- | --- |
| Markdown | `.md`、`.markdown` | 开启 |
| 文本与文档 | `.txt`、`.rtf`、`.docx`、`.pptx`、`.xlsx`、`.odt`、`.epub`、`.pdf` | 开启 |
| 代码 | `.py`、`.js`、`.ts`、`.rs`、`.html`、`.css` | 关闭 |
| 配置文件 | `.json`、`.yaml`、`.toml`、`.xml`、`.ini` | 关闭 |

取消一类文件后，该类文件不再进入索引和检索，原文件及文件浏览不受影响。代码仓库需要自行开启代码、配置文件，或使用 CLI 的 `--types` 指定扩展名。

![全局文件类型与索引设置](/images/product-file-settings-cn.png)

### 其他格式与转换组件

“文本与文档”统一控制纯文本和内置文档，默认开启。TXT、RST 直接读取；以下文档优先使用内置anydoc（启用MinerU时，受支持的文档先交给MinerU）：Word（`.doc`、`.docx`、`.docm`）、PowerPoint（`.ppt`、`.pps`、`.pot`、`.pptx`、`.pptm`、`.ppsx`、`.ppsm`）、Excel（`.xls`、`.xlsx`、`.xlsm`、`.xlsb`）、OpenDocument（`.odt`、`.ods`、`.odp`）、RTF、CSV、EPUB 与文本型 PDF。

“其他格式”列出扫描 PDF、图片、音视频、邮件、Apple iWork 和部分文档模板。未启用MinerU时，普通文本型PDF使用内置解析器。点击“选择”勾选所需格式；已启用MinerU时，其支持的图片等格式可直接应用。其他格式缺少本地组件时，点击“安装并应用”，在确认窗口安装后再应用选择。文档与音视频组件按所选格式分别安装，扫描文件不会自动下载组件。

未启用MinerU时，PDF检测到需要OCR的页面，或内置解析器明确返回不支持时，会使用已安装的Docling。启用后按[模型设置](/zh/docs/models#mineru-文档解析)中的MinerU优先顺序处理。未安装时，索引详情会显示所需操作；安装后重新索引即可。损坏或加密文件会显示解析错误。

独立图片使用轻量 OCR 路径识别文字，不加载面向扫描 PDF 的版面与表格模型；扫描 PDF 和需要完整版面结构的文件仍使用 Docling 文档管线。两种路径都完全离线运行。连续处理多张独立图片时，后台会复用 OCR Worker，模型不会逐张重复加载；空闲 Worker 会自动退出并释放资源。增加“转换并行数”可同时处理多张图片，但并发过高会造成 CPU 争用和发热，吞吐量不一定继续提升。

- **全选 / 清空选择**：一次选中或取消全部转换格式。没有选中格式时，不启用额外格式；已开启的内置文档解析不受影响。
- **应用**：应用格式选择；在全局设置里，还需保存设置。
- **转换并行数**：默认 1，范围 1–16，所有文件夹共用，下次索引任务生效。实际并行数还受共享资源预算约束；已有保存值继续保留。
- **转换内存**：默认自动读取电脑的物理内存，可在[运行参数](/zh/docs/preferences#运行参数)调整总预算比例和单任务预算。所有 Docling 任务合计预算为物理内存的一半，单个任务上限为四分之一；低内存机器尽量保留 4 GiB 的 OCR 运行空间，但不超过总预算。例如 64 GiB 电脑的单任务上限为 16 GiB，总预算为 32 GiB。单任务统计包含其子进程；预算不足时后续任务排队，无法读取物理内存时显示错误。
- **卸载相关组件**：删除 SAG Wiki 安装的文档与音视频组件、运行环境、识别模型、FFmpeg 和下载缓存；保留原文件、转换后的文件和已有索引；内置文档解析继续可用。

处理顺序为：先索引直接支持的文本，再并行解析内置文档及已启用的其他格式，完成的转换结果继续加入索引。已索引内容可以先行搜索，无需等待全部转换结束。

转换结果存放在已添加根目录中的 `.sag-converted/`，保留原子目录结构，例如：

```text
资料/报告.pdf
→ .sag-converted/资料/报告.pdf.md
```

macOS 默认隐藏以点开头的目录。内置解析不会上传文件；Docling 的扫描件、音视频等处理可能需要额外下载识别模型，首次处理包含模型准备时间。升级解析器后，重新索引会更新未被手动修改的内置文档转换结果。

### 下载失败时导入离线文档组件

在文件解析支持安装窗口中，选择 **导入离线组件**，再选择已经解压的完整文档识别组件目录（目录下应有 `manifest.json`）。软件校验平台、组件版本和文件完整性，并执行样例转换；通过后再点击 **应用所选格式**。若之前已有文件解析失败，安装后重新索引对应文件夹。

组件需包含 Python 运行环境、识别依赖和模型，单独下载的 Python 或模型文件不能代替完整组件。目前此入口只支持文档组件，音视频仍使用在线安装。导入失败不会自动转为联网下载；可以重新选择目录，也可以点击重试进行在线安装。

#### 只有 uv 下载失败时

如果错误提示无法下载运行环境管理器（例如访问 `github.com/astral-sh/uv` 超时），可以用浏览器打开错误中的地址下载 uv 压缩包（Windows x64 为 `uv-x86_64-pc-windows-msvc.zip`），解压后点击 **导入离线组件**，选择解压后的目录。软件确认 uv 版本与当前应用要求一致后，跳过这一步下载，继续在线下载 Python、依赖和模型。

后续步骤仍需联网。若对应地址也无法访问，可在系统中设置以下环境变量，重启 SAG 服务（例如运行 `sag service restart`）后重试：

| 下载内容 | 环境变量 | 说明 |
| --- | --- | --- |
| Python 运行环境 | `UV_PYTHON_INSTALL_MIRROR` | 指向 python-build-standalone 的镜像地址 |
| 识别依赖 | `UV_DEFAULT_INDEX` | PyPI 镜像，例如 `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 识别模型 | `HF_ENDPOINT` | Hugging Face 镜像，例如 `https://hf-mirror.com` |

依赖按固定哈希校验，镜像内容与官方不一致时安装会失败，不会装入被篡改的文件。完全无法联网时，请改用完整离线组件。

请向管理员或维护者获取匹配当前系统、架构和组件版本的完整目录；如收到压缩包，先解压再选择。当前正式版 Release 未单独提供完整离线组件下载，不要把应用安装包当作组件包。离线导入入口随包含该功能的应用版本提供，0.2.7 正式包没有此入口。

![下载失败后的离线文档组件导入入口](/images/product-offline-component-cn.png)

组件提供者可使用仓库的 `scripts/package-docling-component.py`，从可独立搬迁的 Python 运行时、依赖目录和模型目录生成带校验清单的完整组件。组件在目标机器复制并验证后启用，不必放进应用安装目录，也无需配置服务端口。

### 自动监听文件变化

默认开启。新增、修改、删除和重命名文件时，后台按规则更新索引。关闭后不要把旧索引当成最新内容，需要时手动重新索引。重新开启会触发文件检查。

监听由共享后台服务执行。关闭桌面窗口不会等同于停止该服务。

### 显示隐藏文件夹

默认关闭。此开关只影响右侧文件列表：开启后可显示隐藏文件夹；左侧仍隐藏。它不控制哪些文件进入索引，索引范围由类型和排除规则决定。

### 索引并行数

默认 8，范围 1–64，下次索引任务生效。只调整并行数不会重建现有索引。处理大型文件时可降低并行数以减少资源占用。

文本索引准备阶段共用 512 MiB 预算，每个文件至少预留 64 MiB。实际并行数受该预算限制，预算不足时后续文件排队等待。程序整体内存还包含数据库、缓存等额外占用。

单文件分块预算最低为 16 MiB，标题按最终分块计算，合并段落不会重复累计标题开销。超出资源限制的文件会在索引历史中记录原因，原文件保持不变。

### 排除索引的目录名称

每行填写一个目录名称。默认包含 `.git`、`node_modules`、`dist`、`target`、`.venv`、`venv` 和 `__pycache__`。这些目录可以继续浏览，但不纳入索引。

精细的路径或文件规则放入 `.sagignore`，支持通配符、目录规则及 `!` 反向规则。它与全局排除、文件类型选择共同决定最终索引范围。

### 重新索引与索引历史

全局的 **重新索引** 按已保存的文件类型与排除目录检查全部已添加目录，只更新有变化的索引。存在未保存的相关设置时，先保存再执行。

**索引历史 → 查看** 用于检查进度、完成状态和失败详情。索引过程中可以查看当前已处理数量；失败时核对文件路径和错误，不要仅依据总文件数判断是否全部完成。

较长的表格行会分段索引，不需要手动换行；检索结果仍对应原文件的位置。索引受到文件大小和内存预算限制，超过限制时会明确报错，不写入不完整的索引。

索引详情按 **文本索引 → 文件转换 → 转换结果索引** 显示处理阶段，进度对应当前阶段。已索引的内容可以先行搜索。点击 **暂停索引** 后，正在处理的文件完成收尾再暂停；点击 **继续索引** 恢复任务。

侧栏底部显示当前阶段、进度和“部分失败”等状态。较长文字会自动换行，右侧关闭按钮始终可用；点击状态文字可查看具体失败文件。

关闭失败提示后，应用会记住当前失败信息，重新打开界面时不再重复显示。新一轮索引仍会显示进度；失败信息变化时会重新提示。已关闭的失败详情仍可通过文件页的索引状态卡片或 **索引历史 → 查看** 打开。

### 最近索引与失败详情

索引详情按文件夹展示最近一次记录，更早记录可展开查看。失败记录提供原因说明和受影响文件，可通过文件条目定位原文件。清空索引记录只移除历史，不删除已有索引。

![索引失败详情](/images/product-index-failure-cn.png)

**已移除的文件和文件夹 → 恢复** 会重新加入被排除的路径并开始索引。仅在希望重新检索这些内容时恢复。

## 单个文件夹的索引设置

从对应文件夹的菜单打开 **索引设置**，可为该文件夹单独选择原生文件类型和转换格式。设置作用于当前目录及没有独立设置的子目录；子目录自己的设置优先。

选项写入该目录的 `.sagignore` 管理区段，已有手写规则会保留。

![单个文件夹的索引选项](/images/product-folder-options-cn.png)

- **保存**：保存选项并按新规则更新索引。
- **重新索引**：清除当前文件夹的旧索引，再按选项建立新索引；其他文件夹及原文件不受影响。
- **取消**：放弃未保存的选项修改。

文件夹级的“重新索引”会重建当前目录；全局“重新索引”按已保存规则检查并更新变化内容，两者的范围和处理方式不同。

## 网页剪藏目录

[网页剪藏](/zh/docs/web-clipper)可以独立保存网页。需要索引时，在网页剪藏设置页点击“添加剪藏文件夹”，选择扩展实际保存目录；加入后按现有规则监听变化。

首次创建知识库时，程序会建立 `Documents/sag-wiki/clippings`，并将 `Documents/sag-wiki` 作为默认文件夹加入。已有知识库和用户移除的目录不会因重启而被重新添加。
