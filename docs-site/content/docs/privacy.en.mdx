## Where data is stored

Location: **Settings → Data and privacy → Application data location → Open directory**.

The application data directory stores SQLite indexes, folder records, settings, model keys, conversations, citations, tool logs and drafts. Different installation methods may use different directories; open it from the app you are actually using.

Original files stay in the folders you added. Editing and saving Markdown changes the original file. Removing an index or uninstalling the app is a different operation.

## Change the application data location

In the desktop app, open **Settings → Data and privacy → Application data location** to see the full path, open the folder or select **Change location**. Choose an existing empty folder, check the current and new paths, then select **Move and restart**.

The app stops the shared background service, copies indexes, settings, keys, conversations, drafts and conversion results stored inside the application data directory, updates internal paths, saves the new location and restarts automatically. Documents inside the data directory are copied with it; documents and conversion results outside it stay in place. Reindexing is not required. The desktop app and CLI versions that support this feature share the new location. Remote service autostart follows the new location if enabled, and existing MCP and API key folder permissions continue to work.

The old directory is kept as a backup and continues to use disk space. Allow enough free space and keep the app open during migration. Unsaved settings on this page will not be retained. Copy or validation failures leave the original location selected and appear in the confirmation dialog. The destination must be empty and neither directory may contain the other.

If the saved location is unavailable at startup, reconnect the original drive, or use the startup prompt to select a retained folder containing an existing SAG database. Choosing a backup does not merge newer records from the unavailable location.

If the app starts with `SAG_DATA_DIR` or `SAG_DESKTOP_DATA_DIR` set, these environment variables take precedence. The UI explains the override and disables changes; remove the variables and restart first. This action is unavailable in the web client.

## Network requests

| Operation | Data flow |
| --- | --- |
| Native text indexing, quick search, browsing, local relationship graph | Local processing; no answer model or Jev required |
| SAG2 deep search and CLI semantic search | Questions, candidate passages and necessary context go to the configured Jev service |
| Q&A | Questions, relevant history, tool results and citations go to the answer model; retrieval also uses Jev |
| Automatic search summaries | Questions and selected results go to the selected summary model |
| External MCP | Accesses local or remote resources according to the tool parameters and service |
| Document parsing with MinerU enabled | Original documents go to the selected 302.AI or MinerU official service; results are downloaded locally. Connection tests do not upload files. |
| Updates, conversion components and recognition models | Downloads files from the relevant distribution service |
| Document sharing | After confirmation, selected Markdown and referenced images are uploaded to temporary sharing storage; anyone with the code can download while it remains valid |

Keys are kept in files accessible to the current user. Other processes running as that user may still read them. Remove keys and sensitive content before sharing logs or application data.

## Cleanup actions compared

| Action | Removes | Preserves |
| --- | --- | --- |
| Clear all conversations | All conversations, reasoning and tool-call logs, including previously deleted conversations | Original files, knowledge base and indexes, model settings and keys |
| Remove all folders | All registered folders and their indexes | Original files, conversations, drafts and model settings |
| Clear all data | Conversations, folders and indexes, search history, model settings, keys and drafts; resets settings | Original files |
| Uninstall conversion components | SAG-managed Docling, its runtime, recognition models and download cache | Original files, converted files and existing indexes |

The first three actions are under Data and privacy and each requests confirmation. Conversion removal is under **File settings → More file formats**. Cancelling the settings dialog cannot undo a confirmed cleanup.

## Index disk usage

SQLite indexes and log files are stored in the application data directory. Removing all folders triggers index-space reclamation; original document directories and conversations are managed separately. Adding the folders again requires reindexing.

Do not manually delete database or log files while the application or shared service is writing them. Use the corresponding application action.

## Limit data access

Add only folders you need, exclude sensitive files with `.sagignore`, and narrow the query scope when appropriate. Bind only necessary external MCP tools to each model. See [Folders and indexing](/en/docs/folders) and [MCP and tool bindings](/en/docs/mcp).

Note import processes Notion, Evernote and Google Keep exports locally. Apple Notes is read through a local read-only database snapshot. Import does not upload notes or modify source data. Imported Markdown and attachments are stored under the library’s normal rules.
