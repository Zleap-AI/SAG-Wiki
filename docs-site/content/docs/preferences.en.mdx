## Saving settings

Open **Settings** from the sidebar, choose a category and select **Save settings** after making changes. In the single-column layout, choose a category from the dropdown at the top. Select **Cancel** or the back arrow in the upper left to discard ordinary unsaved changes, including any previewed language change.

The settings sidebar is grouped into **Application**, **Knowledge base**, **Search & Q&A**, **Connections & services**, and **Other**. **Other** contains **Data and privacy** and **About**.

Testing a connection does not save its configuration. Removing a key, installing or removing a Skill, restoring directories and clearing data are separate actions that run immediately or request their own confirmation.

## General

Location: **Settings → General**.

| Setting | Purpose | Default or choices |
| --- | --- | --- |
| Start page | The first page shown when the app opens | Q&A by default; Q&A or Search |
| Default document mode | Choose how existing Markdown files open | Edit by default. In View mode, select **Edit** in the upper right to open the editor. |
| Interface language | Language of menus, controls and messages | Simplified Chinese by default. Also available in Traditional Chinese, English, Japanese, Korean, and Spanish. |
| After closing the window | Shows the window-close behavior | Continue running in the background |
| Quick start | Reopen the folder, search and Q&A tutorial | Select View tutorial |

The saved interface language also applies to the web workspace, Quick Search, and the desktop tray menu. Core guides are available in [Traditional Chinese](/zh-TW/docs), [Japanese](/ja/docs), [Korean](/ko/docs), and [Spanish](/es/docs).

Reopen the app from the system tray or menu bar. On Windows, launching the desktop shortcut again restores the existing window instead of starting a second desktop instance. On macOS, pressing **⌘Q** or choosing **Quit SAG Wiki** exits only the desktop client; the service keeps running and CLI and MCP remain available. On Windows, choosing **Quit SAG Wiki** stops the standalone service and waits for cleanup before exiting the client. CLI and MCP connections close; reopening the desktop or running a CLI command that needs the service starts it on demand. If stopping fails, the client stays open and reports the error.

## Network proxy

Choose a proxy mode in **Settings → Network proxy**. Answer models, Jev, MinerU, app updates, Docling component downloads, sharing, and remote HTTP MCP share this setting. CLI sharing reads the saved configuration when it uses the same data directory. Online data imports and their account authorization do not use it.

| Proxy mode | Behavior |
| --- | --- |
| Follow system proxy (default) | Reads the manual HTTP/HTTPS proxy from Windows **Settings → Network & Internet → Proxy** or macOS **System Settings → Network → Proxies**, plus the `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` variables; environment variables take precedence. PAC scripts and auto-discovery are not supported yet |
| Custom proxy | Uses the specified proxy server, with direct connections for bypass addresses |
| No proxy | Always connects directly, ignoring system proxies and environment variables |

With a custom proxy, fill in:

- **Proxy URL**: accepts `http://`, `https://`, `socks5://` and `socks5h://`, for example `http://10.0.0.8:3128`. A bare host and port is treated as an HTTP proxy. Pasting an address such as `http://user:password@host:port` moves the credentials into the authentication fields.
- **Proxy requires authentication**: enter the username and password, which are sent with Basic authentication. Like API keys, the password stays in the local application data directory and never enters the settings database; leave it blank when reopening settings to keep it, and turning authentication off removes it. A password without a username cannot be saved.
- **Bypass proxy for**: a list separated by commas, semicolons or line breaks of domains (`corp.example.com` also matches its subdomains), suffixes starting with a dot, IPs, networks (`10.0.0.0/8`) or patterns with `*`. `localhost` and loopback addresses always connect directly, which suits local or LAN model services. The list also applies when following the system proxy, on top of the system bypass rules.

**Test connection** requests the saved answer model address with the settings as entered and reports the route taken, for example "Reached api.302ai.cn through proxy 10.0.0.8:3128 (HTTP 401)". Any HTTP status means the proxy route works; 401 or 404 only means that address needs a key or a different path. In system mode the result also says whether a system proxy was detected. Editing any field clears the previous result, and testing does not save the settings.

Changes apply right after saving, without restarting the desktop app or the background service. Requests in progress keep their connection; the next request uses the new settings. uv, pip and Hugging Face model downloads, as well as MCP servers started over stdio, receive the same proxy through the `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY` variables. An MCP server whose own environment variables name any proxy variable runs entirely on its own configuration. With no proxy these variables are cleared.

## Keyboard shortcuts

Location: **Settings → Shortcuts**. Customize or disable the global Quick Search shortcut here, and view the other keyboard controls.

Quick Search defaults to **⌘⇧Space on macOS** or **Ctrl+Shift+Space on Windows**. Click the shortcut field, press a combination, and choose **Apply shortcut** to save and activate it immediately. Conflicts are reported as errors. Use **Open Quick Search** to try the popup. See [Quick Search popup](/en/docs/search#quick-search-popup).

After turning the switch on or off, choose **Apply shortcut** to save the change.

![Quick Search switch, global shortcut and action buttons](/images/product-quick-search-settings-en.png)

## Runtime settings

File, Model, Search and Q&A settings each expose their runtime parameters. Common controls are visible directly; workers, memory, batches and caches are under **Advanced runtime settings**. Each group can reset to backend-defined defaults, with server-side range and consistency validation.

![Conversion timeouts and advanced runtime settings](/images/product-runtime-en.png)

| Page | Controls |
| --- | --- |
| File settings | Built-in/Docling timeout, input/output limits, threads, OCR/table options and batches, page limits, memory, text limits and watcher debounce; separate parameters under Configure MinerU |
| Model settings | Retry count, initial/maximum backoff, total deadline |
| Search settings | Decision model concurrency/context, local query workers and query/corpus caches |
| Q&A settings | Folding concurrency and units per batch |

Built-in conversion defaults to 120 seconds; Docling defaults to 1800 seconds with 60 extra seconds for process cleanup. Converted text defaults to 16 MiB, matching the downstream indexing input limit. Raise the output, index input, decoded/prepared text and total preparation budget together when larger text is needed. Memory per job set to 0 means automatic. Actual concurrency also respects conversion workers and reserved memory.

Changes apply to new tasks. Running tasks retain their startup settings. Timeout, concurrency and cache changes do not rebuild indexes. OCR, table, page and parser changes refresh the relevant conversions on subsequent scans. An anydoc timeout discards the result while its native worker may run until the library returns; Docling terminates its process tree on timeout.
