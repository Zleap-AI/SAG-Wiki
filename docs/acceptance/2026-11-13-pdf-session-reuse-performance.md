# 同一 PDF 分段复用模型：实现与真实文件对比

状态：实现、回归、中英文文档同步与完整真实文件对比已完成；优化版有两次短暂外部编译采样，结果作为本机单次观测。未发布安装包。

提交整理说明：本报告的完整 PDF 测量先于 PR 与 GitHub `main`（`9a874f1d8b18d36efb7fc6460402fe2eaa9b3a6f`）整合。整合保留了失败文件重试与分段进度，并补充失败 PDF 重试不阻塞新文件的回归；本轮未重新执行 300 页整文计时。以下性能数据仍对应原固定二进制，不代表整合后提交的重新测量。

## 范围

用户要求保持当前 CPU 策略和识别能力，优先减少重复启动开销。本次在已完成分阶段索引的版本上继续优化；“优化前”不是最初未分阶段的 origin/main。

本地多分段 PDF 使用一个短生命周期 Docling 会话，多个分段串行共享 Python 进程、转换器和模型。仍为默认 2 个推理线程，OCR/表格/模型/识别批量/渲染参数不变。分段缓存、原始页范围、原子发布、兼容后端回退、取消、超时和原有内存许可保留。整个文档结束、失败或停止时释放会话，不跨文档常驻。云解析与单次转换路径保持原样。

失败进程在备用后端申请资源前释放。父进程保留并读取子进程退出前发出的最终错误码，避免退出竞态丢失兼容回退或资源错误。会话先于临时 PDF 输入释放，避免 Windows 文件句柄阻碍目录清理。Windows Worker 复用已有 Job Object 监督机制；原生 Windows 行为尚未在本机执行验收。

## 条件

- 同一份 `300_1.pdf`，300 页、92,288,891 字节；SHA-256 为 `e611d487102bcc20662022f1665fef2ed978001bdd9830467091d76ec95fe928`。
- Apple M4 Pro、12 个逻辑 CPU、24 GiB 内存、macOS 26.2，接入电源。
- 固定 Release 二进制；本地 Docling `2.140.0-documents.1`、QPDF 12.4.2。
- 默认转换并发 1、索引并发 8、推理线程 2；OCR 与表格开启，云解析关闭。
- 按用户确认，正式对比复用前轮已验证的相同旧二进制无编译基线，优化版另行运行，两轮不连续。每轮使用全新 SQLite、转换目录和分段缓存；模型文件从固定组件快照用 APFS 克隆，QPDF 也使用固定本地副本。准备复制与编译不计入应用索引耗时。
- 测量 `Store::scan` 的基础提取、增强、分块及实际查询路径，不包含桌面窗口渲染。
- 测量期间不运行本任务的构建、测试或文档服务器。每秒采样外部编译器、进程树 RSS 和解析 Python 进程。
- 系统文件缓存未清空，普通桌面负载与换页无法完全控制；每版一次完整测量，不作通用统计显著性或吞吐倍率承诺。

本机记录的整文耗时减少 **68.881 秒（6.47%）**，RSS 峰值记录较低；确定实现的结构变化是把同一 PDF 的 6 次进程/模型初始化合并为 1 次。两轮不连续、系统状态不同且只有一次优化版完整测量，不能把全部耗时/RSS 差异归因于模型复用，也不宣称通用倍率。基础索引路径没有因本次改动提速，首次可搜索的少量差异按运行波动理解。

**测量限制：** 旧版基线的 1,000 次编译器采样均为零。优化版共采样 933 次，其中两次在运行约 733 / 736 秒处记录到 1 / 4 个外部编译器，其余采样为零；因此优化版不是完全无外部编译活动的一轮。没有扣减任何耗时或隐藏这两次采样。开始/结束系统平均负载分别约 6.91 / 8.52（旧版）、8.27 / 14.12（优化版）；swap 已用约 24,850 / 26,354 MiB（旧版）及 29,454 / 27,997 MiB（优化版）。这些环境差异一并保留，不作为稳定收益承诺。

首次可搜索使用 `search_files("defects")` 的实际首次命中，100 ms 轮询；只代表原文件 61 页文本层提前可用。完整计时包含后台 OCR/表格以及最终发布。RSS 为 1 秒采样的进程树求和，共享页可能重复计入，瞬时峰值可能漏采；不是硬性内存占用上限。

旧版正式计时来自 `qa/progressive-index/after-comparable/`，其每秒编译器采样均为零。后续旧版功能复测的完整 Markdown 与该基线逐字节相同、设置 JSON 完全一致、固定二进制摘要相同。旧版的 6 个 Python 进程计数来自该功能复测；其有编译干扰的完整耗时不参与正式比较。

Python 进程数统计基准程序直接启动的不同解析解释器 PID，不含解释器自身的辅助子进程；原始命令路径与 PID 保留在测量元数据中。任务结束后检查这些直接解析进程是否残留。

## 内容与分段核对

两版完整 Markdown 的 SHA-256 均为 `9b206a0d47f5403cb2a844587f17920f5f579983e5ec1f99c16a2188c736889f`。三词 `defects`、`Cranford`、`Gaskell` 都各命中 1 份文档；六个来源范围标记联合覆盖 1–300 页，最终状态为 `complete`。本文件输出完全一致，不等于已人工评判所有扫描页及复杂表格的准确率。

分段缓存文件时间估算如下，包含解析路由、准备和初始化，阶段不是独立 profiler 测量：

## 排除的测量

第一轮 `qa/pdf-session-perf/before/` 开始时无外部编译器，但运行中原工作目录启动新构建。该轮被停止，原始采样保留，不用于正式完整耗时对比；其他项目未被暂停或终止。

第二轮 `qa/pdf-session-perf/before-comparable/` 完整结束，但采样记录显示约第 757–972 秒间有外部编译活动，同样排除其完整计时。按用户确认，正式比较复用前轮无编译基线，不再反复重跑旧版。

## 验证

- Python 会话协议：3/3 通过；不同分段只构建一个转换器，失败/空结果不覆盖旧输出。
- Rust 全量：536 通过、11 忽略；分阶段索引集成回归：31/31 通过。
- 新增生命周期验证覆盖复用与完成释放、缓存跳过、失败后保留整文并从缓存恢复、取消不发布结果、独占内存预算下的兼容回退、进程退出后的最终错误码，以及成功/失败时输入文件清理顺序。
- 最终错误码竞态和输入释放顺序均先用回归复现失败，再修正验证。
- 独占全局预算的回退测试使用子测试进程隔离，保留原 4 秒取消保护，避免其他并行单测占用它的预算。
- 锁定依赖的 CLI 检查与 Release 构建通过；没有新增依赖或更换模型。
- 真实组件冒烟测试：8 页扫描混合样本 → 7 页表格样本 → 原 8 页样本，在同一 Worker 中连续转换，三份 Markdown 与优化前逐字节相同。
- 独立代码审查及修正后的复审无剩余阻塞项。
- 中英文 models 页面同步，文档站构建通过；两种语言页面均返回 200，新增“常驻”/“resident”正文均能通过文档搜索定位。
- 本次没有界面变化，沿用已有演示截图；未执行原生 Windows/Linux 桌面验收，未发布安装包。
