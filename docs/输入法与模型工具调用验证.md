# 输入法与模型工具调用验证

日期：2026-10-14。

## 输入法问题

原输入框只检查 `KeyboardEvent.isComposing`。macOS WebKit 在确认输入法候选时，可能先结束 composition，再派发回车，导致该值已经为 false。

现在同时处理组合输入状态、`keyCode=229`、compositionend 紧邻的确认回车。确认回车释放后，下一次普通回车正常发送；Shift+Enter 保留换行。问答和搜索表单都受保护，组合输入期间不阻止输入法自身的默认行为。

回归测试使用真实 App 组件派发浏览器事件，并断言后端 `run_query` 调用次数。修复前两种确认回车场景均错误调用后端，修复后均不调用。另验证正常发送、换行、搜索框确认及表单保护。

参考：[WebKit 输入法事件顺序问题](https://bugs.webkit.org/show_bug.cgi?id=165004)。

## SAG2 工具流程

问答模型收到问题、必要历史和 `sag2_search` 工具定义，由模型选择是否调用及检索问题。工具内部执行原有 BM25、Jev 与多跳检索；结果作为 tool 消息送回模型，再生成带引用的回答。普通问候可以直接回答。最多执行三次工具调用，之后仅允许生成回答。

- 工具参数只有 query；文件夹范围和 @ 引用从界面固定传入，模型不能扩大范围。
- 不再预先固定执行检索，也不再另外调用追问改写模型；模型结合历史构造检索问题。
- 多次工具结果使用连续且稳定的引用编号，重复片段不会产生新编号。
- 每次请求的预算包含历史、工具定义、调用记录、原文及输出预留。预算不足时按完整片段减少证据，不截断原文。
- 问答历史记录每次 SAG2 查询及纳入的片段数，界面可展开查看。
- 搜索页仍直接调用 SAG2。
- 流式接口的空 ID 片段不会覆盖已经收到的工具 ID。

实现遵循 [Chat Completions 工具调用协议](https://developers.openai.com/api/docs/guides/function-calling)。

## Jev 接口问题

真实测试发现约 5.8 万 tokens 的评分请求返回 `max_tokens_exceeded`。每批估算预算从原版 64000 降至 32000；候选集合、评分指令和多跳规则不变。共享证据累计过长时，按分数优先保留完整片段，将共享证据与最大单题估算控制在 24000 tokens，预留分词差异空间；未超限的请求保留原证据和顺序。预算触发时提供给 Jev 的背景会减少，可能影响相关性判断。若服务仍明确返回 `max_tokens_exceeded`，只将该批问题对半拆分，保留相同的共享证据；单个候选仍超长时保留错误。固定响应对照测试继续验证原算法。

服务返回 HTTP 529 `system_overloaded` 时，按现有短暂网络错误策略重试，最多四次；持续失败仍显示错误，不返回虚构结果。

## 验证结果

42 项 Rust 测试、14 项前端测试通过。原 SAG2 固定响应对照通过；新测试包含模型自行选择查询、两次工具调用、稳定引用编号、拒绝范围覆盖参数、三次调用后停止、取消、输入法事件，以及 Jev 超长分批与 HTTP 529 重试。

真实模型使用配置的 qwen3.6-flash 和 jev-latest，总上下文 4096、输出预留 512。所有文件问题均由模型主动发起工具调用，没有强制工具调用；普通问候没有检索。
