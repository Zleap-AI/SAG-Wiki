# MCP 与模型设置

2026-10-16 更新：“问答设置”包含提示词、工具绑定、上下文与请求三个板块，服务配置与启用开关合并在“工具绑定”中，每个服务只显示一张卡片，可展开连接设置并配置当前模型的工具权限。

2026-10-15 更新：内置 SAG 已扩展为 search、list、read、grep 四个 MCP 工具，支持按模型逐项选择。最新参数和配合方式见 [SAG 内置 MCP 工具](SAG内置MCP工具.md)，验证结果见 [更新记录](更新记录.md)。下文保留此前阶段的实现和验证记录。

## 使用

- 设置 → 问答设置 → 上下文与请求：每轮工具调用上限，默认 3，可设为 1–100。一次问答中所有 SAG2 和 MCP 调用合计计数。达到上限后要求模型用已有结果回答。
- 设置 → 问答设置 → 提示词 / 工具绑定：按回答模型分别保存系统提示词和 MCP 服务绑定。提示词留空使用内置默认值。
- 设置 → 问答设置 → 工具绑定：添加远程 Streamable HTTP 或本地 stdio 服务，测试连接后显示服务提供的工具。启动参数每行一个。
- HTTP 请求头和 stdio 环境变量填写字符串值的 JSON 对象，留空保留原值，填写 `{}` 清除。凭据单独保存在权限为 0600 的应用凭据文件中，移除服务时同步清除。
- 通用服务默认在执行工具前确认，并展示服务、工具及参数。可在服务配置中调整。模型仍受单轮总次数限制。

## 示例服务

[DeepWiki 官方 MCP](https://docs.devin.ai/work-with-devin/deepwiki-mcp) 提供公开仓库文档查询，无需密钥。示例地址为 `https://mcp.deepwiki.com/mcp`，包含 `read_wiki_structure`、`read_wiki_contents` 和 `ask_wiki_question`（实际连接返回的名称）。它查询公开仓库，不用于读取本地文件。

## 实现边界

- 使用官方 Rust MCP SDK `rmcp`；关闭未使用的服务端和认证功能，连接随问答建立，结束后释放。本地基础功能不需要常驻 Node 或 Python。只有用户添加的 stdio 服务会按指定命令启动。
- 当前支持 Streamable HTTP 和 stdio，未实现旧 SSE 地址和 OAuth 登录流程。
- 模型调用名经过内部映射，界面展示原服务名及工具名；参数按 JSON 传递，本地命令不经过 shell 拼接。
- 工具返回内容计入原有上下文预算；超出预算时向模型返回明确错误。MCP 外部资料保留链接，SAG2 本地片段继续使用原文定位引用。

## JSON 导入与按工具启用

在“设置 → 问答设置 → 工具绑定 → 导入 JSON”粘贴配置，点击“导入配置”。支持 `mcpServers`、VS Code 的 `servers`，以及单个服务对象。示例：

```json
{
  "mcpServers": {
    "DeepWiki": {
      "url": "https://mcp.deepwiki.com/mcp"
    },
    "Local": {
      "command": "/完整路径/可执行文件",
      "args": ["每项参数单独填写"],
      "env": {"API_KEY": "填写实际值"}
    }
  }
}
```

- 导入只添加待保存的配置，不启动命令、不自动连接。同名服务会报告冲突，不覆盖原有配置。
- HTTP 可填写 `headers`，stdio 可填写 `env`。凭据单独保存，不进入 SQLite 设置。暂不处理变量占位符、JSON 注释、旧 SSE 或 OAuth。
- 测试连接后保存工具名称和说明；切换设置页面或重开应用仍能选择。
- 在“问答设置 → 工具绑定”中，可为当前模型开关内置 SAG2，或启用 MCP 服务并逐项选择工具。不同模型分别保存所选工具。
- 新发现的工具不会自动加入已经明确选择过的工具列表。未选择的工具不提供给模型，也不能被调用；全部关闭时不连接该服务。
- 旧版只有服务绑定的配置继续生效，第一次获取工具列表时记录当前工具选择。

## 对话中的调用详情

- 展开 MCP 调用卡片可查看参数、返回文本与结构化内容；“原始 JSON”保留完整返回数据。
- 调用卡片默认收起，摘要显示运行、完成或失败状态；展开后显示服务提供的错误或连接、超时、参数解析错误，停止和拒绝分别显示对应原因。
- 返回结果与错误随问答历史保存，重新打开后仍可查看。较长内容在卡片内部滚动，不截断保存内容。
- 超出模型上下文预算时仍保存完整返回结果，同时说明该结果未发送给模型。
- 旧版本没有保存的返回结果无法恢复，展开时明确提示，不重新调用工具来补写历史。

- 覆盖服务返回错误、连接中断、参数解析失败、手动停止，以及返回结果和错误的历史保存。

## 发送与工具默认状态

- 发送新消息时立即滚动到底部并恢复跟随输出；发送后手动向上滚动仍会暂停跟随，回到底部后恢复。
- 内置和 MCP 调用统一默认收起，运行和失败只更新摘要状态。用户手动展开后，状态变化不改变展开状态。
- SAG2 与已启用的 MCP 工具同时提供给模型，不设固定优先级，可组合调用，共用每轮次数和上下文预算。仍保留各工具的范围与确认设置。
- 已复现旧版发送时停留在历史位置、运行/失败时自动展开的问题；修复后 99 项界面检查、57 项后端检查通过，原生应用重新打包成功。
- 原生客户端使用真实 DeepWiki 调用生成长目录；从顶部阅读位置点击发送后，立即定位到新消息。工具卡片保持收起；随后手动上滚仍能保留历史阅读位置。691 个原始文件复核无改动。

## 按模型开关 SAG2

- 新模型和旧配置默认启用 SAG2，已有 MCP 选择不变。
- 关闭后不向该模型提供 `sag2_search` 定义；如果模型仍返回该工具调用，后台直接拒绝执行。
- 关闭 SAG2 不影响已启用的 MCP 工具。全部工具关闭时发送普通聊天请求，不附带空工具列表。
- 开关只影响该模型的问答工具，不影响搜索页面。
- 自动验证：100 项界面测试、61 项后端测试通过，覆盖独立模型配置、旧配置默认值、关闭后仍可调用 MCP、全部工具关闭的普通聊天和拒绝未启用的 SAG2。
- 原生客户端保存关闭状态后，真实模型成功完成 DeepWiki 调用，未产生本地检索片段；重新打开设置仍为关闭。测试后恢复原模型的 SAG2 启用状态，并打开工具设置页供查看。
