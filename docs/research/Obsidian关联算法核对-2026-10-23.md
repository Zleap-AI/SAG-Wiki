# Obsidian 关联插件的切分、评分和链接写入

核对日期：2026-10-23。

本次读取公开源码及锁定版本的依赖源码，没有运行插件、安装模型或修改用户笔记。结论适用于下列源码快照；设置、提供商及安装版本会影响实际行为。

## 结论

| 插件 | 内容处理 | 如何得到文件相关度 |
| --- | --- | --- |
| Smart Connections | 文件和结构化块分别生成向量；文件输入过长会截断 | 文件模式直接比较文件向量；块模式直接返回各块，默认检索不合并块分数 |
| Similar Notes | 递归切分正文，每块单独生成向量 | 对命中的块按文件去重，保留最高分 |
| Semantic Auto-Linker | 重叠切片，保存各片向量及归一化汇总向量 | 相关笔记查询用当前文件汇总向量，给候选文件评分时取其最佳分块；默认内置模型还会重排 |

“把分块向量平均”“把分块相似度平均”“取分块最高分”是不同操作。不能从插件使用了嵌入模型，就推断它采用哪一种。

## 1. Smart Connections

### 文件输入与块输入是两条路径

默认结果集合为 `smart_sources`，评分算法为 `similarity`，后处理为 `none`，默认返回 20 项。[默认设置](https://github.com/brianpetro/obsidian-smart-connections/blob/3bfe2b259fda93d7935ffb5d530fc8e99ba90c34/src/collections/connections_lists.js#L35)

文件输入由“文件路径 + 正文”组成，先按 `max_tokens × 3.7` 估算字符预算，从尾部截断；文件向量单独生成，没有先合并全部块向量。[文件输入](https://github.com/brianpetro/jsbrains/blob/5e93a615a1bbcbe2bb06ad414de9708568b407b6/smart-sources/actions/get_embed_input/markdown.js#L34)

块解析器识别 Markdown 标题层级、标题下连续正文、顶层列表项、代码区等结构。它不会统一按照“每 N 个字”做滑动切片；空行本身也不总是结束正文块。[解析器](https://github.com/brianpetro/jsbrains/blob/5e93a615a1bbcbe2bb06ad414de9708568b407b6/smart-blocks/parsers/markdown.js#L30)

父标题块可能包含子块范围。Smart Environment 按预计截断损失，在父块与子块方案之间选择待嵌入的集合，避免父子范围重复进入同一选择。若不可再分的块过长，仍然会截断。块输入包含标题路径上下文和该块正文。[块选择](https://github.com/brianpetro/obsidian-smart-env/blob/e8f5e0f909ac15c1cdc9242d8a48bd109b54e390/src/items/smart_source.js#L248)、[块输入](https://github.com/brianpetro/jsbrains/blob/5e93a615a1bbcbe2bb06ad414de9708568b407b6/smart-blocks/actions/get_embed_input/markdown.js#L18)

默认内置模型配置为 BGE-micro-v2、384 维、512 tokens。模型前处理还会计数并裁剪超长输入。因此“文件模式”不保证覆盖长文件的全部正文。[模型配置](https://github.com/brianpetro/obsidian-smart-env/blob/e8f5e0f909ac15c1cdc9242d8a48bd109b54e390/src/adapters/embedding-model/transformers_v4_worker.js#L9)、[截断](https://github.com/brianpetro/obsidian-smart-env/blob/e8f5e0f909ac15c1cdc9242d8a48bd109b54e390/src/adapters/embedding-model/transformers_v4.worker.js#L245)

### 评分与汇总

当前选中的文件或块提供一个查询向量。检索器对指定集合逐项计算余弦相似度，取最高的若干项，过滤自身、失效向量和不符合范围的条目。文件模式比较文件向量，块模式返回块级条目；这条默认路径没有按文件平均或取最大值汇总所有块。[检索流程](https://github.com/brianpetro/obsidian-smart-connections/blob/3bfe2b259fda93d7935ffb5d530fc8e99ba90c34/src/items/connections_list.js#L105)、[余弦计算](https://github.com/brianpetro/obsidian-smart-env/blob/e8f5e0f909ac15c1cdc9242d8a48bd109b54e390/src/modules/embeddings.js#L609)

模型参数中的 `pooling: mean` 发生在一次输入内部，不能据此说插件平均了所有文件块。Pro 可另外选择反馈加权和重排模型，其配置需与默认流程区分。[池化配置](https://github.com/brianpetro/obsidian-smart-env/blob/e8f5e0f909ac15c1cdc9242d8a48bd109b54e390/src/adapters/embedding-model/transformers_v4_worker.js#L16)、[Pro 评分与重排说明](https://smartconnections.app/docs/connections/)

## 2. Similar Notes

### 切分

使用 LangChain 的 Markdown 递归切分器。块大小为 `min(512, 提供商报告的上限)`，重叠参数为 100，长度单位由提供商的计数方法决定。[插件切分配置](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/infrastructure/LangchainNoteChunkingService.ts#L16)

锁定的切分器版本为 `@langchain/textsplitters 0.1.0`。其 Markdown 分隔符依次包含二至六级标题、代码块结束标志、分隔线、空行、换行、空格和单字符。先按较大的结构拆分，超长部分再递归细分，再把较小部分组合成块。重叠是组合时尽量保留的尾部范围，不保证每对相邻块恰好重叠 100 个真实 token。[切分器实际源码](https://unpkg.com/@langchain/textsplitters@0.1.0/dist/text_splitter.js)

计数方式存在提供商差异：内置模型使用 tokenizer；OpenAI 接口使用字符比例估算；Ollama 使用 UTF-8 字节数估算。因此 512 不能统一换算为 512 个中文字。第一块另加笔记标题，其他块仅使用正文；标题在切分后加入，没有预留其长度预算。[内置计数](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/domain/service/transformers.worker.ts#L168)、[OpenAI 计数](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/domain/service/OpenAIEmbeddingProvider.ts#L162)、[Ollama 计数](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/domain/service/OllamaEmbeddingProvider.ts#L115)、[索引输入](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/application/NoteIndexingService.ts#L295)

### 每块检索，再按文件取最大值

当前笔记的每个块分别查询 15 个候选块；合并结果后按文件路径去重，保留最高分，并降序排列。没有平均分或命中次数加权，也没有相关度模型重排。[主流程](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/domain/service/SimilarNoteFinder.ts#L58)

公式为：

```text
文件 B 的分数 = 所有已返回、属于 B 的命中块中的最高分
```

它受每个查询块只返回 15 个候选的限制，不能说成完整遍历了所有文件的所有块对。多个候选块可能来自同一文件，文件去重之后也不会补查至预期文件数量。[去重与排序](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/domain/service/SimilarNoteFinder.ts#L77)

向量库为锁定版本 `@orama/orama 3.1.1`。本次另读其发布包源码，确认该版本在这条路径逐项计算余弦相似度；不是从库名推断使用近似索引。插件将阈值传为 0，再使用库返回的原始分数。[插件调用](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/adapter/orama/OramaDatabase.ts#L278)、[Orama 向量实现](https://unpkg.com/@orama/orama@3.1.1/dist/esm/trees/vector.js)

含义示例：如果某个已返回块对得分 0.92，而同一文件其他已返回块对分别为 0.20、0.15，该文件保留 0.92。这个分数说明存在强局部匹配，不能直接说明两篇文档整体都相关。

## 3. Semantic Auto-Linker

### 切片和整篇向量

索引文本包含标题、别名、清理后的全文和标签。默认按约 1000 个 JavaScript 字符单位切片，重叠基准为 120；边界尽量落在窗口后半段的空格处，每块重复加入标题，因此含标题后的实际块长度可超过 1000。它没有按 tokenizer 计数，中文文本的边界行为会不同于空格分词文本。[索引文本](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L1124)、[切片实现](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/embedding-passages.ts#L6)

每块分别生成向量，同时保存：

```text
整篇向量 = 将全部分块向量逐维相加，再归一化
```

没有按块长度加权；方向等价于对分块向量作等权平均后归一化。[向量汇总](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/embedding-passages.ts#L28)

### 相关笔记的查询

当前笔记的汇总向量作为查询。候选检索以分块为索引项，使用 HNSW；按文件去重后，给每篇候选的分数为“查询向量对该文件全部分块的最高余弦相似度”。没有分块时才比较其整篇向量。[当前笔记查询](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L409)、[HNSW 建立](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L883)、[目标评分](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L1074)

默认内置模型方案另对每篇候选的向量最相似三块做交叉编码器重排，取三块中的最高重排分。重排查询使用当前标题及摘要前 350 个字符单位。Ollama 提供商没有实现该重排步骤。[重排调用](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L418)、[重排实现](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L609)

### 行内链接建议是另一条流程

从正文提取短语，并保留附近上下文；使用短语向量检索与 MiniSearch 词法检索，再做倒数排名融合：每路贡献 `1/(60 + 排名)`，排名从 1 开始。关键词分数不直接与余弦相似度相加。[混合检索](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L562)、[排名融合](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/retrieval-ranking.ts#L29)

默认内置重排模型将“短语”和“短语加上下文”分别与候选块比较：同一块的两次分数取较小值，再在至多三块中取最大值。用意是要求同一个块同时支持短语及上下文。该重排分是原始模型分数，不是已校准概率。它与余弦分数是两个字段。[同块取小、跨块取大](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/semantic-index.ts#L614)、[交叉编码器](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/relevance-reranker.ts#L52)

相关笔记的语义路径没有结果时，界面还有词法规则推荐：共有标题词乘 2，加共有标签乘 3。因此出现推荐不总能证明该次使用了向量结果。[调用条件](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/main.ts#L816)、[词法评分](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/footer.ts#L4)

## 4. 如何把关联写入 Markdown

### Smart Connections 与 Similar Notes

推荐视图本身不向正文插入链接。Smart Connections 可拖动推荐到编辑器创建链接，也可复制结果列表后自行粘贴。Similar Notes 的拖拽、搜索弹窗插入和编辑器建议选择，是明确写入链接的动作；链接目标由 Obsidian 的路径解析接口生成。[Smart Connections 说明](https://smartconnections.app/docs/connections/)、[Similar Notes 写入代码](https://github.com/joybro/obsidian-similar-notes/blob/fc907991d3d08e2e406f7145329164137edead84/src/editor/registerEditorDropHandler.ts#L12)

### Semantic Auto-Linker

接受并应用建议后有两种写入模式：[正文链接](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/matcher.ts#L712)、[文末列表](https://github.com/ysf-ad/semantic-auto-linker/blob/44b30a38fcfa7b43b38483d6567d0828f66623bc/src/footer.ts#L54)

```markdown
正文：参见 [[状态字典]]。
保留显示文字：参见 [[目录/状态字典|状态说明]]。

## See also
- [[目录/状态字典|状态字典]]
```

上例展示格式，未写入用户文件。文末标题默认 `See also`，可配置；正文模式可保留原匹配文字作为显示别名。源码只写链接，未生成“为什么有关”的解释段落。已有同名二级标题时，文末写入器会替换该标题至下一个二级标题之间的内容。

### 明确链接与相似关系

`[[笔记名]]` 或 `[[目录/笔记名|显示文字]]` 指向明确目标，供 Obsidian 解析为出链、反向链接和内置关系图。语义推荐可以独立保存在插件索引中，不需要事先写进正文。相似度高仅提供候选，不能单独证明支持、反驳或因果关系。
