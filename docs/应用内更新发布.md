# 应用内更新发布

客户端在应用内下载并校验更新，下载完成后显示“重启并更新”。关闭设置页不会中断下载；退出整个应用后，需要重新下载。更新只替换程序文件，不清除知识库、会话或本地原文件。

## 签名密钥

本机私钥：`releases/updater-signing/sag-wiki.key`。该目录已被 Git 忽略，私钥权限为仅当前用户可读写。请单独安全备份，不能上传到 GitHub 或随安装包分发。后续版本必须使用同一私钥签名；客户端公钥已写入 `src-tauri/tauri.conf.json`。

更新签名与 Apple 公证相互独立，不需要 Apple 账号。

## 构建更新包

构建时提供 `TAURI_SIGNING_PRIVATE_KEY`（私钥路径或内容）和 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（本机生成的密钥密码为空）。版本号必须高于已发布版本；下面的 `0.1.6` 仅作为示例，实际发布时统一替换。

macOS：

```sh
export TAURI_SIGNING_PRIVATE_KEY="$PWD/releases/updater-signing/sag-wiki.key"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=''
npm run tauri -- build --config src-tauri/tauri.updater.conf.json --config '{"version":"0.1.6"}'
```

Windows 在构建机器安全配置同一签名私钥后，构建时叠加 Windows 和更新配置：

```text
npm run package:windows -- --config src-tauri/tauri.updater.conf.json --config '{"version":"0.1.6"}'
```

macOS 使用生成的 `.app.tar.gz`，Windows 使用 NSIS `.exe`。原有 `.dmg` 和 `.exe` 安装包仍供首次安装使用。

## 生成发布文件

两端构建完成后运行：

```sh
npm run package:updates -- --version 0.1.6 \
  --macos '/path/to/SAG Wiki.app.tar.gz' \
  --windows '/path/to/SAG Wiki-setup.exe' \
  --notes '/path/to/release-notes.md'
```

脚本默认使用上述本机私钥，也支持 `TAURI_SIGNING_PRIVATE_KEY` 和密码环境变量。它会签名两个平台的更新包，核对签名密钥与客户端公钥一致，并在 `releases/0.1.6/updates/` 生成更新包、`.sig` 和 `latest.json`。

把这些文件与原有安装包一同上传至 GitHub 的 `v0.1.6` 正式 Release，再将该版本设为最新版本。`latest.json` 的下载地址指向同一 Release。缺少清单、签名错误或下载失败时，客户端显示错误并保留原版本，不会打开浏览器。

官网更新源采用同样的 `latest.json` 格式，两个平台分别使用 `darwin-aarch64`、`windows-x86_64`，每项包含 `url` 和 `signature`。

已有旧客户端需要先安装一次包含本次改动的新包，之后才能使用应用内更新。仅修改 GitHub 上的安装包，无法给旧客户端增加此能力。

## 验证范围

- 前端测试覆盖进度、关闭后重开设置、下载和安装失败、重试、未保存文档保护及重复点击。
- 原生测试通过本机 HTTP 服务实际下载签名测试包，拒绝损坏内容，并只替换临时目录中的 macOS 应用，确认测试会话和原文件保留。
- Windows 使用 Tauri 官方更新器启动安装、退出并重新打开程序；发布前还需在 Windows 实机验证完整安装流程。
