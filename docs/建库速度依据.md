# 引导页建库速度依据

首页以与第二页一致的紫色小字显示：**建库约 200 毫秒 / 百万字（折算）**，右侧附信息图标。鼠标悬停或键盘聚焦时显示范围和计算依据，平时保持收起。

## 原始记录

来源：`SAG-Benchmark/output/enterprise_rag/index_1000/summary.json`，历史本地 SAG2 Python 建库实验；8 个建库进程、名义 1,000 字符切分。未重新运行建库，也未修改实验或用户原文件。

| 项目 | 结果 |
| --- | ---: |
| 数据集 | EnterpriseRAG-Bench v1.0.0 |
| 文档数 | 511,962 |
| 索引片段数 | 2,619,356 |
| 已索引正文字符数 | 2,464,517,115 |
| 建库阶段 | 469.31 秒 |
| 完整流程（文件清点、建库、完整性检查） | 511.99 秒（8 分 31.99 秒） |
| 每百万字符的完整流程耗时折算 | 207.7445504 毫秒 |

计算：`511.99 ÷ 2,464,517,115 × 1,000,000 × 1,000 = 207.7445504 毫秒`。界面取整显示约 200 毫秒，采用完整流程而非较短的单独建库阶段。

字符数来自只读打开 `SAG-Benchmark/.cache/sag2/enterprise_rag_1000.sqlite` 后汇总 `chunks` 的字符位置；`SUM(end_char-start_char)` 与每文档 `MAX(end_char)` 的和均为 2,464,517,115，文档数与原报告一致。单位为规范化后的 Unicode 字符数，包含英文字符，不是英文单词数量。数据归档的 2,474,399,575 字节未当作字符数使用。

## 使用范围

这是历史大规模建库的吞吐折算，不是对百万字语料单独计时，也不是检索或回答耗时。历史实验使用 Python 实现，与当前 Rust 客户端的执行路径存在区别。完整语料的历史报告未单独记录硬件型号，因此不借用另一项小样本测试的设备信息。实际耗时随设备、文件数、格式和正文内容变化。
