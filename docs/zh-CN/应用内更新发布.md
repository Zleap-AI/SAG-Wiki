# 应用内更新发布

[English](../en/app-update-publishing.md) · [文档目录](README.md)

main 的产品改动自动准备版本、打 tag、完成检查和签名后发布正式 Release。纯文档、CI 和发布工具调整不发版。不再逐版人工批准，也不需要人工发布草稿。PR 检查与 main 分支保护继续保留。

## 一次性启用与密钥配置

`release` Environment 保留签名密钥隔离和仅 `v*` tag 可访问的限制，取消 required reviewers 和等待计时器。迁移已有环境需要仓库管理员权限。在包含本次改动的代码合并后，先检查，再显式应用：

```sh
node scripts/migrate-release-environment.mjs
node scripts/migrate-release-environment.mjs --apply
node scripts/release.mjs verify-environment
```

迁移不会创建标签、触发构建或发布版本，不读取或更换已有密钥。应用前应确认没有运行中或等待审批的旧部署；迁移工具会拒绝在它们存在时应用。先取消旧运行，再迁移，之后按需重新运行失败任务。本次 PR 准备不会修改在线环境。

首次配置密钥时，已有密钥应继续使用；仅在没有既有密钥时生成一次：

```sh
node scripts/generate-updater-key.mjs --output /secure/signing-recovery
node scripts/configure-release.mjs --key-file /secure/updater.key --password-file /secure/updater.password
```

若首次创建环境后校验提示管理员可绕过保护规则，在 Settings → Environments → release 中关闭管理员绕过选项，再重新校验；这是一次性环境配置，不是逐版审批。

恢复目录及密钥文件必须受权限保护，且不能放入仓库。独立保存加密密钥和密码的恢复备份；GitHub Secrets 不是唯一恢复副本。客户端公钥须与私钥匹配，`requireSignedVersion` 保持开启。Apple Developer ID 和公证凭据同样保存在环境 Secret 中；密钥值不得进入日志、源码或制品。

## main 自动发布

1. 产品改动合并到 main 后，自动准备工作流判断当前推送是否需要发布。纯文档、CI 和发布工具调整跳过；混合产品改动会发布。
2. 准备任务串行分配新的 patch 版本，统一桌面与 CLI 的 manifest、lock 文件和 Tauri 配置，并生成确定性的更新说明。它生成 main 提交的发布子提交，不直接回写受保护的 main。
3. 创建指向发布子提交的版本 tag，并显式调度桌面发布工作流。不能依赖 `GITHUB_TOKEN` 推送 tag 再触发另一条 push 工作流。同一来源的重试接续既有标签，不移动或覆盖已存在的标签。
4. 发布校验允许 main 上的普通版本提交，以及自动准备的合法发布子提交。后者必须通过父提交来源与确定性元数据差异校验，不能仅凭 tag 名称或提交说明放行任意分支代码。
5. macOS/Windows 的 Rust 测试与正式编译并行，保留前端、文档、实际安装包与包内 CLI/Jev 检查。macOS 自身检查通过即可签名、公证，不等待 Windows。
6. 所有必要检查、来源与摘要校验通过后，组装更新包、签名并生成构建来源证明，再自动发布。最终发布串行判断版本顺序；较旧任务晚完成时不会夺走 Latest 标记。

main 的源码版本可能落后于最近的自动发布版本，这是生成发布子提交而不回写 main 的结果；下载与更新以正式 Release 为准。无需为每次小改动手工修改所有版本文件。自动版本生成也必须保持两个平台和更新清单版本一致。

## 失败重试与产物复用

优先使用 Actions 的 **Re-run failed jobs** 接续失败运行。若准备阶段已创建标签但调度失败，重试应接续同一标签。不要删除并重建标签、覆盖正式制品或强制移动版本。

发布按同一提交的平台和检查阶段复用可信结果，核验原始生产任务及最新执行次数，失败的平台不使另一平台的有效结果失效。运行中的较早来源采用有界等待；缺失或失效阶段补跑。缓存命中不等于测试通过，测试和安装包检查不得被跳过为未经验证的成功。

签名前下载 macOS 原始产物并校验摘要；完成签名后仍等待 Windows 和所有公共检查。最终检查绑定已签名的原始输入，不切换到另一个未验证的产物。草稿只是内部上传与校验阶段；完整性、检查、签名或公证失败都不能自动发布半成品。已发布版本不能覆盖修补，应生成更高版本。

## 检查下载与恢复

macOS DMG 用于手动安装，带公证信息的 app archive 用于应用内更新；Windows NSIS EXE 用于安装和更新。更新包版本受签名保护，客户端保持验签。

```sh
gh attestation verify /path/to/downloaded-installer --repo Zleap-AI/SAG-Wiki
```

来源证明、SHA256 和更新签名各有用途，均不能替代真实安装及数据保留检查。托管运行器检查不代表所有客户设备已验收。实际发版耗时仍须通过启用后的运行记录测量。
