# SAG 独立后台服务与桌面统一内核实施计划

[English](../en/service-unification-plan.md) · [文档目录](README.md)

日期：2026-10-18

实施时的验收记录：内核迁移已实现，本机验收通过；当时尚未验证正式发行包和 Windows 安装。当前发布情况以 GitHub Release 及对应版本的验收结果为准。

## 1. 目标

让桌面端和命令行连接同一个常驻 SAG 服务。服务由 `sag` 可执行文件启动，独立管理知识库、索引、文件监听、模型配置与检索。桌面端作为可选界面，关闭后不影响 CLI。

每个用户数据目录只运行一个服务。该服务统一持有 SQLite、文件监听器、检索缓存和网络客户端，避免重复初始化、版本不同步及重复监听。

保留用户当前的使用方式：

- 只安装 CLI，也能完成首次配置、添加文件夹和搜索。
- 安装桌面端时，自动准备所需 CLI 和服务。
- `sag "完整问题"` 继续作为默认语义搜索入口，现有参数和 Skill 入口保持有效。
- 添加文件夹自动索引；文件变更按监控设置更新；沿用 `.gitignore`、`.sagignore` 和子目录排除规则。
- 索引只保存文件信息、标题、位置和检索词项。原文片段从本地文件按位置读取。

## 2. 当前实现与需要迁移的部分

当前进程关系与模块边界见[架构设计](架构设计.md)。

| 部分 | 当前状态 | 目标状态 |
| --- | --- | --- |
| 内核代码 | 桌面和 CLI 共用 `sag-core`，分别编译 | 内核只在常驻服务进程中运行 |
| 桌面启动 | 直接打开数据库、启动监听及 CLI 服务 | 连接服务，必要时启动服务 |
| CLI 执行 | 优先连接桌面，连接失败后在本进程加载内核 | 连接常驻服务，必要时启动服务 |
| 生命周期 | 桌面退出会结束其承载的服务 | 桌面退出后服务继续运行 |
| 对外接口 | 主要支持状态、配置、添加、移除、搜索和匹配 | 覆盖桌面全部知识库操作及事件 |
| 大文件传输 | CLI 请求上限 32 KB、响应上限 512 KB | 普通消息保持有界，大文件使用分块传输 |
| 构建与安装 | 开发版从 debug 目录更新 CLI，正式版从资源目录更新 | 明确区分开发产物和正式产物，按构建身份检查版本 |

现有单实例锁和只读查询连接可以复用。当前单实例锁服务于进程所有权，不应扩展为所有查询共用的独占锁。

## 3. 目标结构

```text
桌面界面 ── 本机客户端 ──┐
                         ├── SAG 常驻服务（sag 的服务模式）
sag 命令 ── 本机客户端 ──┘      ├── SQLite 与检索缓存
                                ├── 文件监听与索引任务
                                ├── BM25 / SAG2 / 模型请求
                                └── 配置、会话、草稿与工具调用
```

默认采用当前已有的本机 TCP 通信方式：仅监听 `127.0.0.1`，使用随机端口和当前用户私有连接记录。保留随机令牌认证，不添加 Web 框架或外部可访问的端口。

### 3.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `sag-core` | 检索、存储、索引、模型和工具的实现；保持不依赖 Tauri |
| 独立协议模块 | 请求、响应、事件、版本与错误类型；不依赖数据库或模型实现 |
| 本机客户端模块 | 发现服务、版本握手、发送请求、接收事件、取消和断线处理 |
| `sag` | 终端入口及服务启动入口；普通命令执行时只使用客户端 |
| 桌面后端 | Tauri 与服务之间的适配，以及窗口、托盘、文件选择等系统操作 |
| 桌面前端 | 展示内容、输入、设置界面、HTML 渲染和交互状态 |

最终桌面依赖中移除 `sag-core`，仅依赖协议和客户端模块。桌面不再直接创建 `Store`、监听器或检索执行器。

### 3.2 服务生命周期

1. 桌面启动、CLI 搜索、添加目录或配置时，先检查现有服务。
2. 服务不存在时，启动 `sag` 的内部服务模式。普通搜索语法保持不变。
3. 多个客户端同时启动时，依靠每个数据目录的进程锁选出一个服务；其他客户端等待它就绪后连接。
4. 服务启动完成后才原子写入连接记录。进程失效时，根据连接结果和进程身份处理过期记录。
5. 桌面退出不终止服务。提供明确的服务停止入口，停止时结束监听、取消请求、完成必要事务并释放锁。
6. 第一版不增加操作系统开机自启配置。

`sag status` 只检查现有状态，不为查看状态启动服务。需要服务的操作负责自动启动。

## 4. 必须保持的约束

### 数据与索引

- 沿用当前用户数据目录、SQLite 和设置，进程迁移本身不触发全库重建。
- `documents`、`chunks` 不增加原文正文列；FTS 继续采用 `content=''`。
- 保留原文件哈希、字节范围、行列位置和读取时的版本校验。
- 保留未变化文件跳过、检索统计缓存、BM25 缓存和 HTML 图片编码排除。
- 沿用用户保存的切片长度和其他检索参数，不借迁移修改检索策略。
- 会话、引用记录和草稿的现有文本存储行为单独保留，不混入文件索引。

### 并发与取消

- 支持 20 个同时提交的检索请求。查询之间不增加全局独占锁。
- 写事务只在确实需要写入时持锁；同一会话的写入按会话协调。
- 每次请求有独立 ID、超时、进度和取消状态；一个客户端取消请求，不取消其他客户端的请求。
- 客户端断开后清理其请求，仍连接的客户端继续工作。
- 保留请求范围、路径和符号链接检查，不因迁移扩大目录访问范围。

### 通信与大文件

- 为请求、响应和事件定义类型，协议中不提供任意 SQL 或任意函数执行入口。
- 进度、模型流式输出、索引变化、工具授权都通过有请求 ID 的事件传递。
- 大型文件正文分块传输，分别限制单帧大小与请求资源占用。不能直接把 14–18 MB HTML 填进现有 512 KB 响应。
- 搜索预览继续直接显示检索片段；用户打开文档后才请求全文。HTML 在桌面隔离视图中渲染。
- 密钥只在明确的配置操作中传输，不放进命令参数、连接记录或日志。配置读取接口只返回是否已配置。

## 5. 分阶段实施

每阶段单独交付并验证。中间版本保留可运行状态；新旧服务的对照测试使用隔离的数据目录。

### 阶段 0：统一构建与版本识别

优先完成这一阶段，可以先解决 CLI 漏更新问题。

- 增加可核对的内核构建身份和协议版本。应用版本号不足以区分同一版本的多次构建。
- 桌面与 CLI 的诊断信息显示实际使用的服务版本、进程和执行文件位置，不展示令牌。
- 桌面安装包与 CLI 分发使用同一批原生产物。
- 开发构建使用独立产物和显式部署步骤，避免启动开发版时用旧 debug CLI 覆盖已安装正式版。
- 更新采用暂存、校验、替换步骤，继续尊重现有安装记录和用户修改。

验收：构建一次即可追踪桌面、CLI、服务的对应关系；旧开发产物无法静默覆盖新正式产物。

### 阶段 1：抽出与界面无关的服务能力

- 整理 `src-tauri/src/lib.rs` 中全部命令清单及事件。
- 将查询编排、会话写入、模型配置、工具授权协调迁入服务层。
- 把当前依赖 `AppHandle` 的事件发送改为服务事件接口，Tauri 负责转发。
- 将探索视图的数据计算迁入服务，图谱绘制和交互仍留在前端。
- 抽出独立协议类型，避免桌面为了共享类型继续链接完整内核。

验收：服务层在无 Tauri 窗口的测试中可以执行原有业务；原有结果和错误语义保持一致。

### 阶段 2：实现常驻服务，先接入 CLI

- 从现有 `core/src/cli_service.rs` 的监听、认证、实例锁开始扩展。
- 服务统一启动数据库、索引队列、文件监听、缓存和网络客户端。
- CLI 增加发现、启动、等待就绪与版本握手流程。
- CLI 查询停止在自身进程打开数据库，删除连接失败后直接加载第二个内核的路径。
- 保留首次运行配置向导、安装和 Skill 命令；后台进程不向终端结果中混入日志。

验收：未安装桌面端时，首次配置、`sag add`、搜索、匹配和移除均能使用；多次执行 CLI 连接同一服务，缓存跨命令复用。

### 阶段 3：迁移桌面文件、索引和设置操作

- 迁移目录列表、文件读取和保存、草稿、目录增删、重建索引、设置读写。
- 迁移图片读取及大型 HTML 的分块传输。
- 桌面连接索引进度、目录变化和错误事件；重新连接时先获取完整状态，再接收后续事件。
- 窗口、托盘、Finder / 文件管理器、系统文件选择继续由桌面处理。

验收：桌面与 CLI 看到同一知识库和索引状态；添加、修改、移除目录在两端一致；大型 HTML 打开和图片显示正常。

### 阶段 4：迁移问答、工具和探索操作

- 迁移快速搜索、深入搜索、问答流式输出及会话操作。
- 迁移内部工具调用、外部 MCP 调用和授权确认流程。
- 授权请求只交给发起操作的客户端；客户端断开且仍需人工授权时，结束对应请求并说明原因。
- 迁移探索总览、关联、证据与取消接口。
- 删除桌面对 `Store`、索引线程、检索缓存和模型客户端的直接持有。

验收：CLI 与桌面可以并行使用；任一请求的停止、失败或授权拒绝不影响其他请求；退出桌面后 CLI 正常工作。

### 阶段 5：统一升级与发布

- 新客户端按协议版本握手；不兼容时明确要求升级，不回退到第二套本地内核。
- 升级前停止接收新任务，完成或明确取消在途任务，再停止旧服务并启动新服务。
- 更新失败保留原安装文件；回退时仍只运行一个服务。
- 卸载桌面默认保留独立 CLI、服务和用户知识库；完整卸载应由单独明确的操作触发。
- 校验桌面包和 CLI 分发包的原生产物身份。

验收：升级、重启、只装 CLI、只从桌面开始使用、两端同时安装均通过；正式交付中桌面不再链接检索内核。

## 6. 验证与性能标准

### 功能与数据

| 场景 | 验收标准 |
| --- | --- |
| 同时首次启动两个客户端 | 同一数据目录只出现一个有效服务、一个监听器 |
| 桌面退出后执行 CLI | 服务继续可用，不重新准备整份知识库 |
| 20 个并发查询 | 无全局查询独占锁；结果对应各自请求 |
| 取消、超时、断开 | 仅影响对应请求，客户端及时结束等待 |
| 文件变化及忽略规则 | 两端一致，缓存及时失效，原文件保持完整 |
| 原文与引用 | 结果内容、哈希、字节位置和行列与原文件一致 |
| 数据库存储 | 文件正文不进入普通表；FTS 不保存原文内容副本 |
| 大型 HTML | 搜索只展示短片段；打开全文正常渲染图片、样式及内部导航 |
| 模型与 MCP | 流式输出、失败提示、授权、密钥读写均保持现有行为 |
| 版本不同步 | 明确可诊断，不能静默使用旧内核 |

### 性能

使用同一台本机、同一知识库副本、相同参数和相同查询进行迁移前后对照。远程模型耗时单独列出。不同机器或不同接口的时间不混合比较。

- 建立迁移前基线：冷启动、缓存已建立后的查询、连续 CLI 调用、20 并发、索引期间查询。
- 单独记录客户端启动、服务连接、排队、索引准备、BM25、原文件读取与校验、模型请求和界面显示耗时。
- 记录用户点击或执行命令到结果可见的总时间，包含排队时间。
- 固定测试集下，检索内容、排序与位置保持一致；本地检索的中位数和 P95 相对迁移前不增加超过 10%。
- 同机同库重复快速查询以低于 1 秒为验收门槛；迁移前先记录实际基线。
- 连续命令复用缓存；不得恢复为每次执行都遍历、解码整库原文。
- 记录服务与客户端的内存，不允许重复持有两份完整检索缓存。

以上指标用于实施验收，不作为已实现的性能声明。

## 7. 主要风险与处理

| 问题 | 处理 |
| --- | --- |
| 桌面接口范围大，迁移遗漏 | 先列命令与事件清单，每阶段按清单逐项核对 |
| 新通信增加延迟和复制 | 复用长连接，普通消息有界，大文件分块，单独计时 |
| 两个客户端同时启动服务 | 单实例锁、就绪握手、连接记录原子发布 |
| 服务升级打断任务 | 明确在途任务处理，客户端收到结束原因 |
| 缓存未随文件变化刷新 | 继续使用索引版本失效机制，并测试跨客户端修改 |
| 开发版与正式版互相覆盖 | 隔离开发产物，正式安装按构建身份更新 |
| 后台进程长期存活 | 提供状态和停止入口，断开连接及时清理请求资源 |

## 8. 建议执行顺序与完成定义

先完成阶段 0，单独交付版本同步保障。阶段 1–2 在隔离数据目录中验证独立服务，再按阶段 3–4 迁移桌面，最后进行阶段 5 的升级与发布验证。

只有同时满足以下条件，才标记整体迁移完成：

1. 桌面和 CLI 的全部目标操作均经过同一个服务。
2. 桌面不再直接打开数据库或运行检索内核。
3. 原文、索引、权限、取消和并发验证全部通过。
4. 同机同库性能对照达到标准，记录真实端到端耗时。
5. 同一构建产物可通过桌面包或 CLI 单独安装，升级不会留下版本不一致的活动服务。

## 9. 实施与本机验收（2026-10-18）

阶段 0–5 的代码迁移已完成：桌面仅依赖协议和客户端；SAG 服务统一持有数据、监听、索引、检索和模型客户端。原文件、数据库格式和检索参数沿用原设置。开发产物单独放在 `src-tauri/bin/development/`，受管理的正式安装不会被开发版覆盖。

| 场景 | 本机结果 |
| --- | --- |
| 独立 CLI | 首次配置、添加、语义搜索、本地匹配、移除及终端安装测试通过 |
| 同时启动 | 两个 CLI 同时添加目录，后续查询复用同一 PID |
| 20 并发 | 20 个模型请求均在首个响应释放前到达；19 个完成、1 个独立取消 |
| 超时与授权 | 超时不影响其他连接；工具授权仅发给发起连接 |
| 同连接分块并发 | 正在接收的分块请求不受另一个请求完成影响 |
| 大型 HTML | 18 MiB 文件经分块传输逐字一致；桌面 HTML 与 Markdown 渲染、高亮正常 |
| 服务生命周期 | 退出桌面后 CLI 可用；重启及异常终止后可恢复；桌面重连并显示 CLI 新增目录 |
| 真实知识库 | 原有三个根目录、历史和配置保留；桌面全库快速搜索 432 个文件，首次实测 673 ms |
| 性能对照 | 同一本机、同一知识库副本、5 个固定查询，各 10 次热查询；内容、排序、位置和总数一致 |
| 热查询中位数 | 原直接调用 44.96 ms，独立服务端到端 47.03 ms，增加 4.62% |
| 热查询 P95 | 原直接调用 366.09 ms，独立服务端到端 372.90 ms，增加 1.86% |

BM25 分数经 JSON 往返存在最多 3.56×10⁻¹⁵ 的浮点尾数差异，不影响排序。所有热查询低于 1 秒。此对照只统计本地快速搜索，不包含远程模型延迟，也不代表 grep 扫描已经提速。

本机检查共 467 项测试通过、3 项手动或外网测试跳过：前端 211、内核 204、CLI 47、客户端 2、协议 3；类型检查通过。独立暂存目录的 CLI 和桌面编译也通过。模型和外部 MCP 的服务迁移测试使用本机模拟模型与 MCP 子进程；未在这次迁移中额外向外部模型发送真实资料。正式安装包签名、公网一键安装和 Windows 实机升级需在发布时验证，本次未生成安装包。

搜索预览保留用户后续明确要求：列表显示片段，右侧直接渲染 Markdown / HTML；不改回仅展示未渲染文本。
