# 长文与代码检索验证

> 2026-10-14 更新：默认回答总上下文上限已改为 65,536（64k）tokens。下文的 16,000 / 4,096 是原验证时的配置记录。

日期：2026-10-14。

## 改动

- 片段长度从目标值改为严格上限，默认 2200 个 UTF-16 单位，在“检索设置 → 片段最大字符数”调整。
- 超长自然段优先在行尾、句末或空白处分开；超长代码优先按行分开。单行仍过长时按字符边界继续切分，不破坏中文或 emoji，也不拆开 CRLF。
- 每个片段保存原始 UTF-8 字节范围，以及起止行列；范围采用结束位置不包含在内的规则。引用内容从原文的这些范围提取，不根据修改过的预览文本推算。
- 设置增加“回答总上下文上限”和“回答输出预留”，默认 16000 / 2048 tokens。输入计算包含系统提示、问题、来源编号和正文、保留的历史，并额外留出 20% 输入余量。不同模型分词器可能不同，因此设置明确标为本地估算；真实模型返回的用量另行记录。
- 预算不足时减少整个来源片段、减少较早的历史；保留的来源重新连续编号。片段原文不在回答阶段裁断。问题本身或任何片段均无法放入预算时，在请求前报告错误。
- 追问改写也受预算限制。输出达到预留上限时保留已生成文本，并明确提示回答未完成。
- 支持常见文本代码与配置文件检索。它们使用原始文本切分，只读预览；Markdown 保持原有编辑方式。默认排除依赖与构建目录。
- SQLite 索引升级时重建旧片段，不修改原文件，旧问答的证据快照继续保留。

## 自动检查

32 项 Rust 测试、9 项前端测试通过。新增覆盖：长单行无损切分、长代码块、CRLF、中文与 emoji 行列、代码中的井号及分隔线、只读代码保护、预算不足时整片筛选、引用连续编号、过长问题拒绝、长历史缩减。原 SAG2 固定响应对照仍通过。

## 真实模型测试

使用用户提供的测试密钥调用真实 `jev-latest` 和 `qwen3.6-flash`。新建的验收资料只放在 `SAG-Desktop/.cache/long-validation/files`，没有扩写用户原文件。

- 长段落：约 88 KB 的 Markdown，正文含一条超过 3 万字符的单行。目标验证码位于该行后半段，检查能否检索并准确引用。
- 长代码块：约 22 KB、600 余行代码的 Markdown；检查末尾函数返回值。
- 现有代码：只读检索 `open-context/src/octx` 中的真实 Python 文件，检查 `logical_path` 的路径拒绝规则及异常类型。

测试设置将总上下文收紧到 4096 tokens，输出预留 512。检查真实服务返回的输入与输出用量之和、来源范围、最长片段及最终答案。最新数据和验证结果见同目录 `long-document-test/results.json`。

测试覆盖 139 个片段；每个片段均核对原文对应字节，长度不超过 2200。引用同一行的不同部分时，起止列号不同，不再只显示同一个行号。

## 范围

支持的是文本格式；PDF、Office、图片和二进制解析未纳入本次实现。此次样本验证不代表任意模型采用相同的分词方式，也不代表所有大型代码库性能已验证。

## 系统密码弹窗修复

原实现在每次启动/读取设置时调用系统钥匙串。开发构建的 designated requirement 使用 cdhash，不同构建的哈希不同，访问旧凭据时会出现系统授权。已移除 keyring 依赖及所有钥匙串访问；当前密钥保存到应用数据目录的 credentials.json，macOS 权限为 0600，通过同目录临时文件原子替换。

不自动迁移旧钥匙串，避免再次触发授权。使用用户已提供的测试密钥配置当前版本。这个方式避免系统密码提示，但文件没有额外加密，同一账户运行的其他程序可以读取。
