# 文件与探索视图验证记录

日期：2026-10-16  
实现：本地文档探索首版  
对应计划：[文件与探索视图实施计划](文件与探索视图实施计划.md)

## 已实现

- 知识库工作区顶部增加“文件 / 探索”，默认文件视图。同一会话按文件夹保存模式、列表滚动、中心、节点位置、缩放、平移和探索历史。
- 当前文件夹及子目录内选择入口，首屏最多 24 篇，按文件名和路径稳定排序。按名称查找入口；单击选中，“设为中心”和“打开文档”分别执行。
- 使用现有 SQLite FTS 召回最多 100 个不同文档，以文档级 TF-IDF 加权余弦相似度排序。每次展开 12 篇，继续展开复用排序快照。
- 最多 80 节点、160 条无向边，文档对去重。支持拖动节点、平移、缩放、适应窗口、回到中心、返回上一探索、重置和移除节点。
- 连线显示共同词，点击打开带遮罩的右侧原文面板。两篇文档按同一个共同词定位，每篇最多读取 3 个片段，返回最多 3 组原文对照，展示路径、章节、行列与高亮。
- 原文读取继续核对文件哈希和原有位置范围。文件变化后撤销旧连线与依据，保留有效节点位置；新增、修改、删除、重命名沿用原有文件事件和增量索引。
- 中英文文案、键盘选择与关闭面板、减少动态效果设置均接入现有组件体系。
- 基础探索不依赖 API 密钥、Jev 或回答模型，不产生外部模型调用。SAG2 检索和问答算法参数没有改动。

## 数据与实现决定

新增 `explore_summaries` 表，每篇最多 64 个词项，包含文件哈希与摘要版本。新索引随原有文件处理同时更新；旧索引按当前中心及最多 100 个候选按需补建。概览和缓存命中不读正文，不调用 `retrieval_corpus()`。

文档频率按当前范围的不同文档 ID 统计，不复用段落频率。摘要去重重复片段、降低通用词影响，过滤公共导入行和版权声明行。它提供词语关联，不能推断引用、因果或观点一致。

计划中的“300 个候选段落”未作为正文评分阶段使用。实际排序阶段使用有限文档摘要，不提取 300 段正文；仅打开依据时读取最多 6 个片段。这保留文档去重和按需读取，减少正文传输。旧摘要缺失时仍需读取相应候选文件，不能将这种首次补建耗时称为缓存命中。

分词缓存原来的 `shift_remove` 会移动后续缓存项。压力测试发现超过缓存容量后出现明显开销，已改为常数时间移除。只改变淘汰次序，分词输出不变，已有 SAG2 排序回归及 8,300 条缓存一致性测试覆盖此变化。

## 自动化验证

前端：默认视图、按需展开、视图恢复、文件变化撤销连线、取消旧请求、依据面板 Esc 关闭、重置首屏外节点、失败后重试原请求、查找已有节点后的选中状态、80 节点上限、原文返回原探索范围、问答范围保持不变。

后端：范围与隐藏目录、真实原文位置、公共导入误关联、版权模板误关联、快照分页顺序、文档对分数对称、修改/删除/重命名、旧索引按需摘要、取消请求、长文中共同词的对齐依据、文件类型设置使缓存失效。

完整回归：前端 33 个测试文件、175 项通过；Rust 后端 157 项通过，2 项手动测试默认忽略。手动的三规模压力测试已单独运行通过。类型检查无错误和警告；Windows x86_64 交叉编译检查通过。测试日志保存在本地 `.cache/explore-*.log`，不随安装包分发。

## Mac 原生操作验证

使用独立应用标识和独立数据目录，测试文件位于 `.cache/explore-native/探索验证`。未向正式知识库写入测试内容。

已实际操作：文件 / 探索切换、4 篇文档的关联与无关项、双文档原文高亮、从子目录文档返回原中心、修改文件后自动关闭旧依据、84 篇测试文档下首屏 24 篇和多轮展开、达到下一批容量限制时保持现有图并提示。

原生验证发现并修复了按名称选择已显示节点时，镜头更新覆盖选中状态的问题。键盘与弹层基本行为同时由前端测试覆盖。77 个节点的原生图可显示及操作，80 节点硬上限由组件测试覆盖；未测量实际帧率，不将此记录称为 80 节点帧率验收。

## 本地性能记录

机器：Apple M4 Pro，arm64，macOS。测试使用未优化的 Rust 测试构建，模型请求为 0。为测试索引查询容量，直接在临时 SQLite 中生成文档、FTS 段落和摘要；这些数据不是用户文件，也不代表真实目录的建库速度。

每篇模拟文档包含中文词项、英文标识符和一个段落，约百字节。每个规模测试 5 个中心，再对同一中心执行 20 次缓存请求。首次关联列为这 5 次中的最大值，样本量不足以作为生产延迟分布结论。

| 文档数量 | 概览 | 首次关联最大值 | 缓存请求 p95 | 摘要 JSON 负载 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 3.5 ms | 48.8 ms | 0.2 ms | 500,629 字节 |
| 10,000 | 38.3 ms | 349.4 ms | 1.3 ms | 5,006,291 字节 |
| 100,000 | 332.4 ms | 2,527.4 ms | 12.7 ms | 50,062,971 字节 |

这轮同时运行构建任务。此前无同时构建的一轮测得 10,000 篇首次关联最大值 222 ms，100,000 篇为 2,417 ms。实际文件长度、共同词分布和磁盘速度会影响结果。

摘要负载均值约 501 字节/文档；这是此模拟数据的 JSON 字节数，不包含 SQLite 页和索引开销。每篇达到 64 个词项时占用会更大。

## 审查与已修复问题

按规范和计划分别审查。发现的重置遗留旧连线、加载时移除节点导致旧请求回写、重试执行错误操作、双方独立截取片段无法配对等问题均已修复，并补充针对性测试。两项审查复核后无剩余阻断项。后续还补充了文件名查询的索引版本校验，避免展示旧版本入口，对应测试通过。

## 尚未验证的事项

- 尚无独立人工标注的真实文档对验收集，没有声称达到 P@5 80%，也没有用 MuSiQue 指标替代文档关联质量。
- 生产方案暂采用加权余弦；加权重合率及加入段落质量的对照实验尚未完成。相同主题但无共同词可能漏掉；共同词存在也不必然代表有实质关联。
- 缺失摘要和后台索引场景已有功能测试，尚无完整大规模延迟分布。实际长文件夹的摘要补建及磁盘额外占用需继续测量。
- Windows 没有可用实机，本轮只能进行交叉编译检查。鼠标、触控板、缩放和动画的 Windows 实际体验仍需验收。
