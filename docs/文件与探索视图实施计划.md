# 文件与探索视图实施计划

日期：2026-10-16  
状态：首版已实现；验证范围与待验收项见验证记录  
适用产品：SAG Desktop，macOS 与 Windows  
技术基础：Tauri + Rust + SQLite，沿用现有 Svelte 界面

本文记录本次讨论形成的产品方向，以及后续实现需要解决的问题。本文中的参数和性能指标均为拟定的验证目标，不代表已经测得的结果。首版已按本计划实施；以下保留原设计目标，实际实现决定、实测结果及未完成验收项见[验证记录](文件与探索视图验证记录.md)。

## 1. 产品目标

在现有知识库页面的顶部增加“文件 / 探索”切换：

- 文件视图负责按目录浏览、打开和编辑文档。
- 探索视图以文档为节点，展示文档之间有原文依据的内容关联。
- 用户可以从一篇文档出发，找到相关文档，并沿着关联继续浏览。
- 每条连线都可以查看关联词和两边的原文段落。

核心使用路径：

> 浏览文件 → 切换探索 → 选择文档 → 查看相关文档 → 查看关联依据 → 打开原文。

第一版首先解决两个问题：

1. 当前文档还与哪些文档相关？
2. 为什么这些文档会连在一起？

“强关联”表示存在较充分的内容关联依据。共同出现词语不能直接证明互相引用、因果关系或观点一致。界面和文案都要保持这个边界。

## 3. 页面结构

### 3.1 顶部切换

保留当前系统标题栏和左侧导航。知识库工作区顶部调整为：

```text
当前位置 / 文件夹             [ 文件 | 探索 ]             当前视图操作
```

- 左侧：当前位置，支持返回上一级。
- 中间：紧凑的分段切换按钮，标签为“文件”“探索”。
- 右侧：仅展示当前视图需要的操作。
- 文件视图保留“新建文档”。
- 探索视图提供“回到中心”“重置视图”，不在画布工具栏重复放置新建入口。

复用现有组件、图标、字体、圆角和黑白配色。切换按钮使用现有 Bits UI 体系实现键盘和焦点行为，不再增加另一套组件库。

### 3.2 文件视图

保留当前文件列表与编辑行为。新增切换按钮不改变以下规则：

- 左侧点击文件夹名称浏览，点击箭头展开或收起。
- 浏览文件夹不修改问答和搜索的范围。
- 文件的打开、编辑、保存和未保存内容确认继续使用现有流程。
- 文件视图计数仍按当前文件列表含义显示。

### 3.3 探索视图

工作区由画布和按需展开的详情面板组成：

```text
当前位置                 [ 文件 | 探索 ]       回到中心  重置视图
探索范围：当前文件夹及子目录     已索引文档数 / 当前显示数

┌──────────────────────────────────────────────────────┐
│                                                      │
│   文档 B ─────── 当前文档 A ─────── 文档 C             │
│                       │                              │
│                     文档 D                           │
│                                                      │
│                                  缩小  放大  适应画布 │
└──────────────────────────────────────────────────────┘
```

点击连线后，从右侧弹出关联依据面板。面板展开时背景适度虚化；点击遮罩、关闭按钮或按 Esc 收起。不要将原文面板永久固定在右侧占用画布。

默认仅在聚焦或悬停的连线上显示关键词，避免所有文字同时叠在画布上。重要信息必须也能通过点击和键盘获取。

## 4. 首次进入与范围规则

### 4.1 首次进入

当前页面是文件夹页面，因此首次切换时可能尚未选中具体文档。建议采用以下流程：

1. 立即展示当前探索范围和已索引文档数量。
2. 在有限范围内展示文档概览，提供按文件名查找文档的入口。
3. 用户选中文档后，以该文档为中心加载关联文档。
4. 后续从文档阅读页返回探索时，恢复原来的中心文档与画布位置。

首屏初始建议最多展示 24 篇文档，按稳定的文件顺序选取，并明确标注“显示部分文档”。它只是起始文档入口，不宣称代表全库最重要或关联最强的文档。

首屏如展示连线，只计算这组可见文档的真实关联。不使用随机连线填充视觉效果。用户选中中心文档后，关联候选必须从整个当前范围获取，不能只在首屏样本中寻找。

### 4.2 范围

- 默认范围为左侧当前文件夹及其子目录。
- 只使用已经接入、允许索引且成功建立索引的文件。
- 显示隐藏文件夹不代表其内容进入探索范围，继续遵循当前索引规则。
- 切换到另一个文件夹时，探索范围随之改变。
- 第一次进入其他文件夹，仍默认显示文件视图；同一会话中返回已浏览文件夹，可恢复该文件夹上次使用的视图。
- 第一版不自动跨知识库增加节点。后续若增加全库范围选择，应由用户明确切换，并持续显示当前范围。

“文件列表中的文件数”和“可参与探索的已索引文档数”可能不同，界面需要分别表达。

## 5. 节点、连线与原文详情

### 5.1 文档节点

节点展示文件图标、文件名以及必要的所属目录信息。同名文件必须能够区分路径。

视觉规则：

- 中心文档使用更明显的边框和底色。
- 选中文档、悬停文档、普通文档具有明确但克制的状态差异。
- 节点大小保持接近，不按文件字数无限放大。
- 长文件名截断，完整名称通过提示或详情查看。
- 优先沿用黑白灰体系；如果需要颜色，只用于少量分组，并同时提供文字说明。
- 没有可靠关联的文档允许独立显示，不强制连线。

节点主要操作为“设为中心”和“打开文档”。单击先选中并展示这两个操作，避免单击既打开文件又触发图扩展。不要将双击作为唯一入口。

### 5.2 关联连线

第一版使用无方向连线。文档内容相近本身不构成引用方向。

连线规则：

- 粗细表示当前评分下的相对关联强弱，分档保持有限。
- 悬停或聚焦时显示少量主要关联词。
- 点击后显示完整关联依据。
- 相同文档对只保留一条连线，A—B 与 B—A 去重。
- 暂不显示“关联度 92%”等容易被理解为概率的数字。
- 在阈值尚未校准前，使用“相关文档”和相对排序，不宣称“强关联”。

### 5.3 关联依据面板

面板至少包含：

1. 两篇文档的名称和路径。
2. 主要关联词与短语。
3. 左右文档中对应的原文段落，标注章节、行列位置。
4. 原文中的关联词高亮。
5. 打开任一文档的操作。
6. 如有更多依据，按组切换查看，避免一次加载全部正文。

第一版每条连线默认展示最有代表性的 1–3 组依据。长段落按现有片段展示，不复制整篇文档到面板。

例如：

```text
文档 A：文件监听说明.md
文档 B：索引更新流程.md
共同内容：文件监听、重命名、增量更新

A：收到文件重命名通知后……
B：重命名时移除旧路径的索引，并处理新路径……
```

解释以可核对的原文和词项为主，第一版不调用模型生成“关联原因”文案。

## 6. 主要交互与状态保留

| 操作 | 结果 | 保留内容 |
| --- | --- | --- |
| 文件 → 探索 | 显示当前文件夹的探索视图 | 文件列表滚动位置、目录展开状态 |
| 探索 → 文件 | 返回当前文件夹列表 | 中心文档、已展开节点、缩放与平移位置 |
| 选中文档 | 突出节点并显示操作 | 当前画布不立即重排 |
| 设为中心 | 加载该文档的关联文档 | 已有节点坐标优先保留，记录探索路径 |
| 展开更多 | 增加下一组关联文档 | 已有排序、节点和连线 |
| 打开文档 | 进入现有阅读或编辑页面 | 保存探索上下文，提供返回入口 |
| 点击连线 | 打开关联依据面板 | 当前中心与画布位置 |
| 回到中心 | 将当前中心节点移回可视区域 | 不清空已展开内容 |
| 重置视图 | 回到当前范围的初始概览 | 不清理文件或索引 |
| 返回上一步探索 | 恢复前一个中心和画布状态 | 不重新读取未变化的数据 |

状态第一版保存在当前应用会话中，不新增长期探索历史数据库。重启后默认文件视图，避免需要维护失效的节点位置与路径。

探索范围单独管理，不复用并修改现有问答 `scope`。从探索进入问答的功能不纳入首版，防止浏览动作意外改变问答范围。

有未保存文档时，离开编辑页继续调用现有保存确认。仅切换文件与探索视图不会写入原文件。

## 7. 文档关联的计算方案

### 7.1 与现有 SAG2 的关系

可复用部分：

- 文档读取、格式解码与索引范围。
- 中文分词、英文规范化和已有停用词处理。
- 词项到段落的全文检索。
- 段落到文档的映射。
- 原文哈希、片段范围与行列位置。

需要新增的部分：

- 文档关键词摘要。
- 文档候选聚合、关联评分和排序。
- 文档对的原文依据选择。
- 探索视图的状态与增量失效处理。

现有 Jev 评分判断的是某个片段是否为回答特定问题所必需的证据。探索视图通常没有用户问题，不能直接使用这一分数表示文档关联强度。

基础探索在本地计算，不自动调用 Jev 或回答模型，也不改变现有 SAG2 问答和搜索的算法、默认参数及调用次数。

基于词项的首版方案可能遗漏“主题相同但表达完全不同”的文档。需要在质量评测中单独记录这类遗漏，不能提前承诺完整语义关联能力。

当前 `retrieval_corpus()` 会读取范围内文档正文。探索请求不能直接调用这一全量读取路径；名称短语和统计资料应从已有摘要或受限数据中获取，同时保持现有 SAG2 路径不变。

### 7.2 计算流程

```text
确定当前文件夹范围
    ↓
读取中心文档的关键词摘要
    ↓
用高价值词项从现有全文索引召回段落
    ↓
按文档聚合、去除中心文档、限制候选数量
    ↓
计算文档关联分数，选出可核对的原文依据
    ↓
返回有限数量的节点和连线
    ↓
用户继续展开时，再加载下一组结果
```

每次以中心文档为起点寻找邻居。第一版不对整个知识库进行文档两两比较，不预生成并长期保存完整关系图。

### 7.3 词项选择

原始词频仅作为一个输入，不直接决定关联强度。词项选择综合考虑：

- 在文档正文中的出现情况，重复出现采用饱和权重。
- 出现在标题、章节中的情况，但同一标题不能因为切分成很多段而重复加分。
- 在语料中的常见程度，降低通用词的权重。
- 完整名称、领域短语与独立词的区别。
- 词项是否集中出现在能够解释文档主题的段落中。

针对代码文件，降低通用语法词、常见导入语句和模板内容的权重。保留有区分度的标识符；不能简单排除所有英文词或下划线词。

仅凭代码导入、相同路径词或模板段落产生的关联，需要在专项样本中检查，不能视为天然可靠。

第一阶段验证词项筛选规则，再确定哪些规则值得进入实现。不要先引入一套未经验证的实体识别系统或大规模词典维护机制。

### 7.4 评分基线

建议先建立一个可以解释、可以对照的本地基线：

1. 对文档词项使用 TF-IDF 类权重和重复次数饱和处理。
2. 使用归一化相似度，减少长文档天然包含更多词的影响。
3. 选择两边实际命中的段落，检查共同词是否集中、是否具有区分度。
4. 每个文档对只保留有限组不重复依据，重复模板不得持续累加分数。

原型阶段比较以下方案：

| 方案 | 用途 | 需要检查的问题 |
| --- | --- | --- |
| 加权词项余弦相似度 | 基础排序 | 截断关键词摘要后是否遗漏重要主题 |
| 加权词项重合率 | 对照排序 | 短文档是否因少量共同词获得过高分数 |
| 基础排序加段落依据质量 | 候选增强 | 是否改善相关性，是否过度依赖重复段落 |

在人工标注样本上确定最终公式和阈值。未验证前不固定“高于某分数必然强关联”的结论。

文档对分数应保持对称。在同一索引版本和相同范围下，A—B 与 B—A 使用相同评分口径。以 A 或 B 为起点召回时，受候选截断影响，发现的邻居集合可以不同；这属于候选召回限制，应单独测试。

### 7.5 词频统计口径

当前 `Store::frequencies()` 返回命中段落数，不能直接称为“出现该词的文档数”。

如果使用文档级 IDF，必须按当前范围统计包含词项的不同文档数量。禁止把段落频率、文档频率和原文出现次数混为一个指标。

先验证通过现有全文索引批量统计有限词项的文档频率是否满足性能要求，并按索引版本缓存。若不满足，再评估增加必要的统计表；不能为了实现探索先复制一套完整倒排索引。

基线如使用段落频率作为近似特征，实验记录必须明确写出，单独测量它与文档频率方案的差异。

### 7.6 共同词与原文解释

- 原始匹配依据保留规范化词项。
- 界面优先显示原文中的可读名称或短语。
- Jieba 搜索分词可能产生重叠词，解释时需要合并或去重。
- 不把经过分词再拼接的内容当作原文展示。
- 高亮需要映射回原文位置；无法可靠定位的词不显示伪造的精确范围。
- 保留每条关联的算法版本、主要词项和原文位置，便于排查错误关联。

## 8. 数据与索引设计

### 8.1 已核对的代码基础

| 当前实现 | 已确认情况 | 对本功能的影响 |
| --- | --- | --- |
| `documents` | 保存文档 ID、路径、名称、哈希等 | 可以定位节点和判断内容版本 |
| `chunks` | 保存所属文档、章节、范围和位置 | 可以定位关联依据 |
| `chunk_fts` | 标题、章节、正文的 contentless FTS5 索引 | 可以召回；不能当作原始正文仓库 |
| `chunk_vocab` | 当前使用列级词汇统计 | 文档级词频能力需新增查询或统计方案 |
| `metadata.version` | 索引内容更新时递增 | 可用于请求一致性与缓存失效 |
| 文档修改 | 保留文档 ID，删除旧片段再生成新片段 | 旧片段 ID 不能作为长期稳定引用 |
| 原文读取 | 读取文件后核对哈希，再恢复片段内容 | 应复用于探索依据面板 |
| `retrieval_corpus()` | 会读取当前范围的文档正文 | 探索热路径不能直接复用这一全量读取操作 |
| 文件监听 | 按变化路径处理新增、修改、删除等 | 探索不能额外启动全目录轮询 |

上述事实来自本次只读代码检查，不代表探索功能已经实现。

### 8.2 文档关键词摘要

如果实测每次从原文生成关键词导致重复读取，可以增加一张有明确容量限制的文档摘要表，记录：

- 文档 ID、内容哈希和摘要算法版本。
- 有限数量的关键词及其局部统计。
- 文档有效词项数量等归一化所需数据。
- 关键词的代表片段定位信息。

每篇文档初始最多保留 64 个摘要词项，作为待验证参数。摘要用于候选选择与局部计算，不视为完整文档词频统计。

摘要更新与该文档原有索引更新一起完成，不重复启动一次文档扫描。已有文档没有摘要时，按实际浏览需求补建；不因为第一次打开探索而强制重建全库。

是否需要持久化摘要、具体字段和存储形式，在第一阶段通过读取成本与数据库体积测试后确定。只允许新增当前功能确实需要的数据。

### 8.3 请求一致性与缓存

请求和缓存至少区分：

- 当前规范化范围。
- 中心文档 ID 与内容哈希。
- 索引版本。
- 关联算法版本。
- 展开页或候选游标。

同一组结果的继续展开使用既有排序快照，不在每次点击时重新排序全部节点。索引变化后明确标记当前图需要更新。

第一版可以采用索引版本级失效，优先保证正确性。只有实测发现失效过于频繁时，再实现按变化文档和词项局部失效。

不长期保存所有文档对，不把整个文件正文复制到浏览器存储，不为一次性浏览引入额外图数据库。

### 8.4 修改、删除与重命名

| 文件变化 | 探索处理 |
| --- | --- |
| 新增 | 新文件索引成功后可被召回 |
| 修改 | 更新该文档摘要，旧哈希的依据失效 |
| 删除 | 移除节点及关联，打开的面板提示文件已删除 |
| 重命名或移动 | 重新解析当前身份与路径，刷新显示及定位 |
| 移出范围或取消索引 | 从当前结果中移除 |
| 读取失败 | 标记不可用，不继续显示旧内容为当前原文 |

当前代码不能保证所有重命名场景都保留原文档 ID。实现前需核对重命名事件处理；不能仅凭文件内容哈希，把两份同内容文件合并成一个节点。

文件变化时不要让整张图突然重排。优先保留可用节点，提示“文件已更新”，再由用户刷新相关结果；已删除内容必须及时撤出。

## 9. 后端接口与前端结构

以下是拟定的功能边界，名称在实施时可调整。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `explore_overview` | 当前范围、首屏数量 | 文档入口、已计算连线、索引状态与版本 |
| `explore_neighbors` | 中心文档、范围、快照与游标 | 下一组关联文档、连线、是否还有更多 |
| `explore_evidence` | 文档对、内容版本 | 关联词、有限组原文依据、定位信息 |

所有范围校验在后端执行。前端传入文档 ID 不代表允许读取范围外文件。

节点返回文档 ID、路径、标题、文件类型和内容版本。连线返回文档对、排序分数、解释词项、依据数量及版本信息。正文仅在打开依据面板时读取。

响应应明确区分：

- 当前文档没有可靠关联。
- 有更多关联文档但尚未展开。
- 索引尚未完成或数据需要更新。
- 请求失败及具体原因。

前端建议按实际职责新增探索画布、节点与依据面板组件，放入现有工作区。不要继续把所有绘制与状态逻辑堆入 `App.svelte`，也不创建通用图编辑器框架。

画布初期采用 Svelte 配合 SVG：节点使用文档卡片，连线、缩放和平移统一维护。现有数据规模上限内先验证交互和性能，再决定是否确实需要额外布局库或 Canvas 渲染。

## 10. 数量限制、性能与轻量化

### 10.1 初始验证参数

| 项目 | 初始建议 | 说明 |
| --- | --- | --- |
| 首屏文档入口 | 24 篇 | 不代表全库完整展示 |
| 一次展开的关联文档 | 12 篇 | 支持继续展开 |
| 单中心候选文档 | 100 篇 | 候选上限与可见数量分开 |
| 单中心候选段落 | 300 段 | 先按文档去重，再限制，防止长文件占满候选 |
| 画布同时可见节点 | 80 个 | 到达上限后提示收起分支或重新选择中心 |
| 画布同时可见连线 | 160 条 | 不无限追加低分连线 |
| 每条连线解释词 | 默认 3 个 | 详情可查看更多 |
| 每条连线原文依据 | 默认 1–3 组 | 按需继续读取 |

这些是首轮测试值。不能把候选数量或画布上限解释成“知识库只有这些文档”或“只存在这些关系”。

### 10.2 性能验证目标

- 切换按钮立即反馈，计算过程中显示明确状态。
- 已缓存结果以 p95 200 ms 内显示为初始目标。
- 约 1 万篇已索引文档下，单中心首次关联查询以 p95 1 s 内完成为初始目标。
- 80 个可见节点时，验证平移、缩放和拖动是否流畅，分别记录 Mac 与 Windows 的帧率和卡顿。
- 退出探索或图布局稳定后，停止持续布局动画与无必要的计算循环。
- 摘要额外占用、首次补建成本、索引更新时间分别测量，不把它们隐藏在“搜索时间”之外。

上述指标尚未验证。需要同时报告冷缓存、热缓存、缺失摘要、后台索引进行中四种情况。若达不到目标，先减少重复读取、限制候选及按需加载，再决定是否增加依赖。

禁止采用的默认路径：

- 每次进入探索重新读取整个知识库正文。
- 全库文档两两评分。
- 每拖动一个节点调用模型。
- 无上限后台力导向计算。
- 为页面建立独立常驻服务、图数据库或第二套全文索引。

## 11. 动效、输入与可访问性

- 文件与探索之间使用短淡入淡出，不出现整页缩放。
- 展开新节点时，优先保持已有节点稳定，新节点从所关联节点附近进入。
- 不在用户拖动、阅读依据或输入搜索词时自动调整镜头。
- 尊重系统减少动态效果设置。
- 画布拖动与节点点击要有移动距离判定，防止拖动后误开文档。
- 支持触控板平移和缩放，同时提供可点击的缩放控件。
- 键盘可选择节点、查看关联依据、打开文档和关闭面板。
- 关联强弱不只依赖颜色；连线详情提供文字依据。
- 中英文界面都验证长文件名、按钮宽度、文本换行与提示文案。
- 小窗口下优先隐藏次要文字，保留中心文档和主要操作，不增加多层滚动条。

加载文案使用“正在查找关联文档”“正在读取关联依据”等与实际任务一致的表述。基础本地计算不显示“模型思考中”。

## 12. 异常与边界情况

| 情况 | 预期表现 |
| --- | --- |
| 没有添加文件夹 | 提示先接入本地文件夹 |
| 文件夹为空 | 显示空状态，可返回文件视图 |
| 有文件但尚无可用索引 | 显示索引状态，不画演示关系 |
| 只有一篇文档 | 显示单节点，说明当前范围没有其他文档 |
| 没有达到展示要求的关联 | 明确提示没有找到可靠关联，不强行补足数量 |
| 部分索引失败 | 可浏览成功部分，同时保留失败详情入口 |
| 中心文档被删除 | 停止继续展开，提示重新选择起点 |
| 依据面板打开期间原文变化 | 取消旧版本精确高亮，提示刷新 |
| 快速切换中心或范围 | 旧请求结果不能覆盖最新请求 |
| 到达画布数量上限 | 提示收起分支或重新选择中心，不直接卡住页面 |
| 查询失败 | 显示具体原因和重试，不伪装成无关联 |
| 网络不可用、未配置模型 | 基础探索继续可用 |

文件内容始终作为数据处理。第一版不执行文档中的脚本，不把正文当作操作指令，不因探索动作移动、删除或改写原文件。

## 13. 验证与验收标准

### 13.1 关联质量

建立独立的文档对样本，至少覆盖：

- 相同主题、不同用词。
- 不同主题、共同通用词很多。
- 共同专有名称，但讨论对象不同。
- 短摘要与对应长文档。
- 两份包含相同模板或免责声明的文档。
- 中英文混合内容。
- 同名文件、同内容副本。
- 代码文件及大量公共导入语句。
- 同主题但观点相反的文档。

每对记录人工相关性、支持段落和误关联原因。调参样本与验收样本按文档分开，避免同一文档的相似片段同时出现在两边。

分别报告：

- 候选阶段能否找到人工确认的相关文档。
- 最终前 5 和前 10 个结果的相关比例。
- 被判定为强关联的结果中，人工确认相关的比例。
- 每条展示连线能否找到支持它的原文依据。

初始质量目标：验收样本中，前 5 结果至少 80% 被人工确认有实际关联；该目标仍需用用户真实使用场景校准。所有展示的依据必须对应原文，定位错误不能用整体平均分抵消。

不能用既有 MuSiQue 问答召回率证明文档关联图的质量。这两个任务需要分别评测。

### 13.2 交互与文件安全

- 文件与探索切换不改变问答、搜索范围。
- 返回文件列表恢复原位置，返回探索恢复原中心与画布位置。
- 连线详情能打开两边文档，路径与定位正确。
- 相同文档对没有重复边，旧请求不覆盖新结果。
- 文件新增、修改、删除、重命名后结果正确更新。
- 有未保存编辑时继续出现现有确认流程。
- 关闭窗口后仍遵循当前后台运行规则。
- 测试前后核对原文件哈希，探索全过程不修改原文件。

### 13.3 性能与平台

采用临时生成的 1 千、1 万、10 万篇不同规模文档，记录机器、系统、文件格式分布、平均长度、索引状态与缓存状态。

至少测量：首屏加载、选中心、展开下一组、打开依据、缩放拖动、首次摘要补建、单文件修改后的刷新。

确认基础探索产生的外部模型请求数为 0。Mac 与 Windows 分别实测；交叉编译成功不能代替 Windows 实机交互验收。

## 14. 分阶段实施与交付

| 阶段 | 工作 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0：数据与算法验证 | 核对统计口径、摘要成本、候选召回、关联评分基线 | 样本文档、标注表、性能与质量记录、已确定的评分口径 | 有可解释依据，能区分真实关联与模板共同词 |
| 1：交互原型 | 顶部分段切换、受控画布、节点选中、连线面板、返回状态 | 使用独立测试数据的交互原型 | 明确点击行为、范围规则与状态恢复，避免无上限展开 |
| 2：本地功能接入 | 接入真实索引、中心展开、文档聚合、原文定位 | 可实际浏览的本地探索视图 | 所有连线有依据；不调用模型；原文件保持不变 |
| 3：变化处理与性能 | 索引版本、缓存失效、删除重命名、取消请求、界面性能 | 边界测试与性能报告 | 达到确定后的容量与延迟目标，无过期引用 |
| 4：平台验收 | 中英文、Mac 与 Windows、打包及回归 | 安装包、用户验收清单、已知限制 | 两端完成实际操作验收，原有搜索问答无回归 |

每阶段只增加下一步所需的内容。阶段 0 如果发现评分质量不足，应先调整候选或解释依据，不用更复杂的画布掩盖质量问题。

第一版不纳入：自动主题命名、全库聚类、手工编辑知识关系、关系图导出、多人共享、自动实体抽取、关系推理、向量数据库、默认模型精排。

这些方向可以后续评估，但不影响本方案的首版闭环。

## 15. 实施前需要明确的决定

1. **首屏概览方式**：先验证“有限文档入口 → 选择中心”的可用性，不承担全库主题概览的承诺。
2. **评分统计来源**：确定文档频率的查询成本，明确是否需要有限摘要表。
3. **候选与展示数量**：用真实文件夹测试首屏 24、展开 12、画布 80 的初始值。
4. **强关联阈值**：取得人工标注结果后确定，未校准时仅显示排序和关联依据。
5. **重命名身份处理**：核对现有路径更新逻辑，决定失效与重新定位方式。

以上决定完成后，再编写正式实现任务和验收数据。本文不将这些待验证事项记为已完成。
